# 11. 关键源码逐段精读

本章不复制整份内核源码，而是保留决定语义的骨架。阅读时在仓库根目录打开原文件，把被省略的审计、cgroup、NUMA、security 等分支逐步补回。

## 1. `rest_init()`：先占 PID，再用 completion 放行

源：`init/main.c:688`

```c
pid = kernel_thread(kernel_init, NULL, CLONE_FS);
/* 查到 PID 1 task，暂时固定在 boot CPU */

pid = kernel_thread(kthreadd, NULL, CLONE_FS | CLONE_FILES);
kthreadd_task = find_task_by_pid_ns(pid, &init_pid_ns);

system_state = SYSTEM_SCHEDULING;
complete(&kthreadd_done);
schedule_preempt_disabled();
cpu_startup_entry(CPUHP_ONLINE);
```

逐句语义：

1. 第一条 `kernel_thread` 消耗下一个 PID，确保 init 是 1。
2. PID 1 不能立刻自由继续；其 `kernel_init()` 首句等待 `kthreadd_done`。
3. 第二条创建 PID 2，并把 task 指针发布为全局 `kthreadd_task`。
4. completion 建立“PID 2 已可用”的同步与内存可见性关系。
5. PID 0 主动调度一次，让新 task 获得 CPU，然后永久进入 idle 框架。

## 2. `kernel_thread()`：函数指针借 stack 字段传递

源：`kernel/fork.c:2626`

```c
struct kernel_clone_args args = {
    .flags = ((lower_32_bits(flags) | CLONE_VM | CLONE_UNTRACED) & ~CSIGNAL),
    .exit_signal = (lower_32_bits(flags) & CSIGNAL),
    .stack = (unsigned long)fn,
    .stack_size = (unsigned long)arg,
};
return kernel_clone(&args);
```

这里 `.stack/.stack_size` 对内核线程不是普通用户栈/大小，而被约定为 fn/arg 的传递槽。x86 `copy_thread()` 识别 `PF_KTHREAD` 后，用 `kthread_frame_init(frame, sp, arg)` 把它们放入首次运行现场。理解结构字段必须结合调用场景，不能只凭名字。

## 3. `copy_process()`：资源获取顺序

源：`kernel/fork.c:1930`

```c
p = dup_task_struct(current, node);
retval = copy_creds(p, clone_flags);
retval = sched_fork(clone_flags, p);
retval = copy_files(clone_flags, p);
retval = copy_fs(clone_flags, p);
retval = copy_sighand(clone_flags, p);
retval = copy_signal(clone_flags, p);
retval = copy_mm(clone_flags, p);
retval = copy_namespaces(clone_flags, p);
retval = copy_io(clone_flags, p);
retval = copy_thread(clone_flags, args->stack,
                     args->stack_size, p, args->tls);
pid = alloc_pid(...);
```

每个真实调用后都有错误判断，这里为突出阶段而省略。要点：

- `p` 在早期只是当前 task 的一个危险副本，尚未公开。
- 调度状态先初始化，但不入 runqueue。
- 共享型资源通过加引用获得，复制型资源通过分配新对象获得。
- `copy_thread()` 准备“将来第一次运行”，不会当场执行子任务。
- PID 和全局关系靠后建立，避免失败对象过早可见。

## 4. `copy_mm()`：一个条件决定进程还是线程式地址空间

源：`kernel/fork.c:1475`

```c
tsk->mm = NULL;
tsk->active_mm = NULL;
oldmm = current->mm;
if (!oldmm)
    return 0;

if (clone_flags & CLONE_VM) {
    mmget(oldmm);
    mm = oldmm;
} else {
    mm = dup_mm(tsk, current->mm);
    if (!mm)
        return -ENOMEM;
}
tsk->mm = mm;
tsk->active_mm = mm;
```

三种结果：调用者是内核线程则 child 无用户 mm；`CLONE_VM` 则同一地址空间增加 users；否则创建独立 mm，并在更深层为可写私有映射建立 COW。

## 5. x86 `copy_thread()`：为什么父得 PID、子得 0

源：`arch/x86/kernel/process.c:112`

```c
childregs = task_pt_regs(p);
frame->ret_addr = (unsigned long)ret_from_fork;
p->thread.sp = (unsigned long)fork_frame;

if (p->flags & PF_KTHREAD) {
    memset(childregs, 0, sizeof(struct pt_regs));
    kthread_frame_init(frame, sp, arg);
    return 0;
}

*childregs = *current_pt_regs();
childregs->ax = 0;
if (sp)
    childregs->sp = sp;
```

父 task 仍沿当前 syscall 调用链返回，`kernel_clone()` 的返回值是子 PID。子 task 复制父进入 syscall 时的寄存器，但把 `ax` 设为 0；第一次调度到 `ret_from_fork` 后恢复这套寄存器，于是用户态看到 fork 在子分支返回 0。

## 6. `wake_up_new_task()`：从构造对象到可运行对象

源：`kernel/sched/core.c:4439`

核心步骤是把新 task 状态改为 `TASK_RUNNING`，选择 CPU，锁住目标 runqueue，激活并 enqueue task，调用 `check_preempt_curr()`。如果新 task 更应该立即运行，它只会推动重调度决定；实际切换仍在合法调度点进入 `__schedule()`。

## 7. `context_switch()`：先 MMU，后 CPU 栈

源：`kernel/sched/core.c:4889`

```c
if (!next->mm) {
    enter_lazy_tlb(prev->active_mm, next);
    next->active_mm = prev->active_mm;
    if (prev->mm)
        mmgrab(prev->active_mm);
    else
        prev->active_mm = NULL;
} else {
    switch_mm_irqs_off(prev->active_mm, next->mm, next);
    if (!prev->mm) {
        rq->prev_mm = prev->active_mm;
        prev->active_mm = NULL;
    }
}
switch_to(prev, next, prev);
return finish_task_switch(prev);
```

`next->mm == NULL` 是切向内核线程；它借用 `prev->active_mm`。切向用户 task 则调用架构层切 MM。`switch_to` 之后代码已经在 next 的内核栈上运行，但变量 `prev` 仍标识刚切出的任务，最后完成延迟清理。

## 8. `__switch_to_asm`：真正的栈指针交接

源：`arch/x86/entry/entry_64.S:225`

```asm
pushq %rbp
pushq %rbx
pushq %r12
pushq %r13
pushq %r14
pushq %r15
movq  %rsp, TASK_threadsp(%rdi)  /* 保存 prev->thread.sp */
movq  TASK_threadsp(%rsi), %rsp  /* 装入 next->thread.sp */
popq  %r15
...
jmp   __switch_to
```

`rdi=prev`、`rsi=next`。callee-saved registers 的压栈顺序必须和 `inactive_task_frame` 布局一致。换 `%rsp` 是分水岭：之后 pop 的是 next 上次保存或 fork 时伪造的现场。

## 9. `exec_mmap()`：原 task 原地换 mm

源：`fs/exec.c:971`

```c
tsk = current;
old_mm = current->mm;
task_lock(tsk);
active_mm = tsk->active_mm;
tsk->active_mm = mm;
tsk->mm = mm;
activate_mm(active_mm, mm);
task_unlock(tsk);
mmput(old_mm);
```

观测重点不是局部 `mm` 的地址，而是提交前后同一个 `current` 的 pid 与 mm。`mmput(old_mm)` 发生在新 mm 已激活后；线程/引用关系会决定旧 mm 是否在此刻真正销毁。

## 10. `do_exit()`：重资源先走，身份稍后走

源：`kernel/exit.c:727`

```text
exit_signals -> exit_mm -> exit_files/exit_fs
-> exit_task_namespaces/exit_thread
-> cgroup/perf/ptrace cleanup
-> exit_notify
-> do_task_dead -> schedule
```

task 不会从 `do_task_dead()` 返回。父进程仍可能需要退出状态，因此 PID/task 的最终解除发生在 wait 路径的 `release_task()`。这也是调试时看到 exit 事件后 task 结构还存在的原因。

## 11. 精读方法

第一次：只沿成功路径，给上述十个路标下断点。  
第二次：从 `bad_fork_cleanup_*` 逆序理解所有权。  
第三次：任选一个子系统（cgroup、namespace、signal、security）插入主线。  
第四次：开启 SMP，研究锁、RCU 和跨 CPU wakeup；不要在第一遍就混入所有并发细节。
