# 10. 术语表、误区与自测题

## 核心术语

| 术语 | 精确定义 |
|---|---|
| task | Linux 的调度实体语境，通常由一个 `task_struct` 表示一个线程 |
| process | 用户语义上的资源容器，常对应一个线程组 |
| `current` | 当前 CPU 正在内核中代表其执行的 task 指针 |
| PID/TID | 单个 task 的 ID |
| TGID | 线程组 ID，通常是用户眼中的进程 ID |
| `task_struct` | task 的中心描述符，连接调度、身份和资源对象 |
| `mm_struct` | 用户虚拟地址空间的总描述对象 |
| VMA | 一段连续、属性相同的虚拟地址范围 |
| `mm` | task 所拥有/共享的用户地址空间；内核线程通常为 NULL |
| `active_mm` | task 当前执行时 CPU 使用的地址空间语境 |
| runqueue | 每 CPU 的可运行 task 与调度状态集合 |
| context switch | 从 prev task 切换到 next task，包括 MMU 与 CPU 上下文处理 |
| COW | fork 后暂共享页面，写入时再复制的策略 |
| zombie | 已退出但尚未被父 wait 消费退出状态的 task |
| reaper | 负责 wait/收养孤儿的 task，常为 PID namespace 的 init |
| `kthreadd` | PID 2，统一处理内核线程创建请求的内核线程 |

## 十个常见误区

1. **“进程和线程用不同结构表示。”** 错：都以 task_struct 为核心，差别主要在资源共享关系。
2. **“fork 会立即复制全部内存。”** 错：通常复制地址空间元数据/页表关系，物理页先 COW。
3. **“exec 创建一个新进程。”** 错：成功 exec 保持 task/PID，替换程序映像和 mm。
4. **“TASK_RUNNING 就是此刻在 CPU 上。”** 错：也包括 runnable、排队等待 CPU。
5. **“系统调用就是进程切换。”** 错：通常只是同一 task 的特权级切换。
6. **“内核线程不需要页表。”** 错：它没有自己的用户 mm，但 CPU 仍使用 active_mm。
7. **“PID 0 是 fork 出来的。”** 错：init_task 静态存在并由启动上下文演化而来。
8. **“kthreadd 就是所有 kworker。”** 错：前者是创建管理者，后者是具体工作线程。
9. **“exit 返回后 task 立即完全释放。”** 错：会保留退出状态，wait/引用计数/RCU 后才最终释放。
10. **“虚拟地址相同就是同一物理页。”** 错：必须结合页表或可靠统计判断。

## 自测题

### 基础

1. 用户态 `getpid()` 与内核 `task->pid` 在多线程进程中为何可能不同？
2. PID 0、PID 1、PID 2 的名字、入口和最终职责分别是什么？
3. `files_struct` 与 `struct file` 的复制/共享有何区别？
4. 为什么每个 pthread 仍需要自己的内核栈？

### 调用链

5. 写出从 `fork` 系统调用到新 task 首次返回用户态的主链。
6. 写出从 `execve` 到 `exec_mmap` 再到 ELF 入口的主链。
7. 写出从 `schedule` 到 x86 栈指针切换的主链。
8. 写出从用户写 COW 页到 `do_wp_page` 的主链。

### 推理

9. 父子 fork 后虚拟地址相同，子写入变量后为什么父值不变？
10. 两个线程切换时为何可能不需要换用户页表，但仍必须换内核栈？
11. 一个线程调用 exec 时，同线程组其他线程为何不能继续存在？
12. 父进程不 wait，为什么子进程退出后仍在 `/proc` 中出现？

### 调试设计

13. 你要证明“exec 不改变 PID 但改变 mm”，最少在哪两个位置记录哪两个值？
14. 为什么不建议给 `__switch_to` 下无条件断点？怎样先缩小范围？
15. 如果 `copy_process` 断点完全没有参数，如何判断是编译优化、符号不匹配还是根本没走到？

## 参考答题要点

1. `getpid()` 返回 TGID；非组长线程的 task PID/TID 不同。
2. 0 为 swapper/idle；1 从 kernel_init 转为用户 init；2 为 kthreadd。
3. fd 表可复制，但表项所指 open file description 常共享引用与偏移。
4. 每个 task 可独立进入内核、阻塞与被调度，必须保存私有内核调用栈。
5. syscall entry -> kernel_clone -> copy_process -> wake_up_new_task -> schedule/context_switch -> ret_from_fork -> user return。
6. do_execveat_common -> bprm_execve -> search_binary_handler -> load_elf_binary -> begin_new_exec/exec_mmap -> start_thread。
7. schedule -> __schedule -> pick_next_task -> context_switch -> switch_mm -> switch_to -> __switch_to_asm/__switch_to。
8. #PF -> do_user_addr_fault -> handle_mm_fault -> handle_pte_fault -> do_wp_page。
9. 页表写保护触发 COW，写方得到私有页。
10. 线程共享 mm，但 task 的 CPU 保存现场和内核栈独立。
11. 新程序映像只能有一致的线程组执行语境，`de_thread()` 收拢其他线程。
12. 父尚未消费退出码，最小 task/PID 信息保留为 zombie。
13. exec 提交前后记录 `current->pid` 和 `current->mm`。
14. 频率极高；先用 sched tracepoint 找 PID，再用 prev/next PID 条件断点。
15. 核对 `info address`/build-id，确认 bzImage-vmlinux 同源，再用函数入口或调用者断点和 tracepoint 交叉验证。
