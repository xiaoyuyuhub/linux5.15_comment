# 01 一张图容纳整个进程系统

## 四条线同时跟

**身份线**回答我是谁、谁创建了我：task → pid/tgid → group_leader → real_parent/children → PID namespace。**资源线**回答我拥有什么：mm、files、fs、signal、sighand、cred、nsproxy。**执行线**回答下一条执行什么：用户 RIP/RSP、内核栈、thread.sp、调度实体。**生命周期线**回答何时出现和消失：静态任务 → 创建 → 可运行 → 运行/阻塞 → 退出 → 回收。

一旦跟丢函数，回到这四条线：这个函数正在创建对象，改变引用，调整状态，还是改变 CPU？例如 `copy_mm` 改资源；`alloc_pid` 建身份；`wake_up_new_task` 让任务可运行；`switch_to` 切执行现场；`release_task` 脱离任务关系并释放相关引用。

```text
编译链接的 init_task（启动 CPU 的 PID 0）
  → x86 启动汇编设置启动栈、页表及 current 相关环境
  → start_kernel：建立内存、调度与任务分配设施
  → rest_init（仍在 PID 0 上下文）
      ├─ kernel_thread(kernel_init) → PID 1
      │     └─ 等待 kthreadd_done → 完成初始化 → kernel_execve
      │          └─ init 程序/本仓库 /init 脚本 → shell/服务
      │               └─ fork/clone → execve → 应用 → exit → wait
      ├─ kernel_thread(kthreadd) → PID 2
      │     └─ 处理 kthread_create 请求 → 内核工作线程
      └─ schedule_preempt_disabled → cpu_startup_entry → idle
```

箭头有两种语义：普通箭头是同一执行流继续；“创建 → 子任务”是创建关系，不是普通同步函数调用。PID 0 创建 PID 1 后，不会像调用函数一样等 PID 1 整体执行完再创建 PID 2。先允许调度，又用 completion 保证依赖。

## 从物理内存到进程

你学的伙伴系统主要管理物理页。slab 分配适合对象大小的内核内存。新 task 的描述符、内核栈、mm、VMA、页表页都需要内存，但用途不同。

|对象|谁拥有/引用|分配或建立入口|释放视角|
|---|---|---|---|
|task_struct|任务、调度器及其他引用者|dup_task_struct → alloc_task_struct_node|引用归零后 free_task|
|内核栈|每个普通 task 独立|alloc_thread_stack_node|put_task_stack 等；不一定等到 task_struct 最后释放|
|mm_struct|共享该地址空间的任务及借用者|mm_init/dup_mm|mmput 与 mmdrop 两级引用|
|vm_area_struct|某个 mm 的映射区间|dup_mmap/mmap|解除映射、exit_mmap|
|页表页|某个 mm 的地址翻译结构|pgd_alloc 等，逐级按需分配|拆映射、释放页表|
|用户物理页|页表、页缓存及其他引用|缺页、COW、文件映射等|引用计数、反向映射和回收协调|

一个 task 自己的描述符不在它的用户堆里。fork 需要马上分配一些内核对象，即使用户数据页被 COW 共享。因此“fork 不复制物理页”最多是普通匿名页的简化主路径描述，不能解释为 fork 不分配内存。

## 两个完全不同的切换

```text
用户线程 A: 用户代码 → syscall → A 的内核代码 → 返回 A 用户代码
                          （可以没有任务切换）

任务 A: 内核里 schedule → 保存 A 栈现场 → 恢复 B 栈现场
任务 B: 继续 B 上次停下的位置 → 可能稍后返回 B 用户态
                          （发生任务切换）
```

中断通常先在被打断任务的上下文或架构指定的中断栈上处理；中断本身不是一个新进程。Linux 内核线程则有真实 task 和可调度的执行流。不能把“都执行内核代码”当作二者相同的理由。

## 先学的边界

主线关注普通 Linux 用户进程、pthread、kthread 和普通 CFS 任务；实时调度、deadline、cgroup 调度层次、NUMA 自动迁移、ptrace、LSM、seccomp、io_uring 工作任务在相应位置说明影响和继续入口。架构有关的寄存器与汇编只针对 x86-64，不套用到 ARM64。

检查题：用户进程调用 malloc 以后，没有立刻增加 RSS，是否说明申请失败？不是。用户分配器可能复用已有空间，或新虚拟映射尚未触页。进程创建与用户物理页分配的时间不是同一个概念。
