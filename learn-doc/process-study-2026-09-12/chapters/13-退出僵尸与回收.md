# 13 程序结束之后，还剩哪些东西

![退出与回收](../diagrams/exit.svg)

## exit、_exit、exit_group 分层

C 库 exit 会处理 atexit 和 stdio 等用户态收尾；系统调用层的 exit 结束当前线程，exit_group 使整个线程组退出。现代 libc 的 _exit 包装可能调用 exit_group，不能把用户 API 与原始 syscall 完全等同。多线程程序 main 返回通常触发进程级退出；pthread_exit 则是线程库的线程结束路径。

信号导致死亡也会汇入退出处理。不要只在 `__x64_sys_exit` 下断点就断言捕获到了所有结束。

## do_exit 主线按资源所有权看

```text
sys_exit / do_group_exit / 致命信号相关路径
  → do_exit
      → 设置 PF_EXITING / 同步线程组计数等
      → exit_mm
          → exit_mm_release → mm_release（clear_child_tid/vfork 等）
          → 清 current->mm、进入相应 lazy TLB 状态
          → mmput：最后 mm_users 才拆用户映射
      → exit_sem / exit_shm / exit_files / exit_fs 等
      → task_work、perf/cgroup 等收尾
      → exit_notify：重设孤儿父关系、通知父、决定自动回收
      → 最后 do_task_dead
          → TASK_DEAD → __schedule
          → 后继 task 的 finish_task_switch 做调度相关收尾
```

这是阅读分组，并非省略号间所有钩子的精确顺序。逐句次序见附录 do_exit 原文。

退出一个共享 mm 的线程，只减少自己的使用引用，不能把其他线程仍在用的整个地址空间拆掉。最后使用者退出时才执行 exit_mmap 的主体释放。文件表和打开文件也按引用处理，不能直接“关闭系统中全部同名文件”。

## zombie 保存的是可收集的结果

`exit_notify` 先设置 `exit_state=EXIT_ZOMBIE`，随后根据线程组、ptrace、父通知规则决定是否 autoreap。普通可等待子进程保留退出状态和足够身份信息，父进程可通过 wait 收集。

zombie 已经不再继续执行用户程序。很多资源此前已释放；保留 task/PID 信息不等于保留整个堆、栈和所有用户页。不要用 `kill -9 zombie` 期望让一个已死的执行流再死一次，应找负责回收的父进程。

但也不能声称任何退出都留下用户可见 zombie：非组长线程、显式 SIGCHLD=SIG_IGN 或 SA_NOCLDWAIT 等规则可以自动回收。ptrace 和线程组最后线程关系会增加分支。

## 父进程 wait 的后半条链

```text
wait4 / waitid
  → do_wait
      扫描可等待子任务、检查选项
      ├─ 没有符合事件：WNOHANG 返回或挂等待队列睡眠
      └─ wait_task_zombie
          取得退出码与资源统计
          WNOWAIT 时保留可等待状态
          常规回收时转换退出状态
          → release_task
              脱离 PID/任务关系、释放相关资源引用
              → RCU 延迟与 put_task_struct 等最后引用管理
```

wait 不负责启动子进程退出；它负责观察/收集。`waitid(..., WEXITED|WNOWAIT)` 可以等到孩子退出却暂不回收，因此本套 zombie 实验无需用 sleep 猜孩子是否死了。

waitpid 返回的 status 是编码值，使用 WIFEXITED/WEXITSTATUS/WIFSIGNALED/WTERMSIG 等宏解释；不要把 raw status 直接当 `_exit(23)` 的 23。

## 孤儿被谁接手

退出的父任务不能继续为子任务承担回收责任。`forget_original_parent`、`find_new_reaper` 等选择同组可用线程、合适的 subreaper 或 PID namespace 的 child_reaper。不是所有孤儿在所有容器环境都直接交给宿主机 PID 1。

进程组、会话、孤儿进程组以及终端作业控制信号是另一层关系，不等于父子树。阅读 `kill_orphaned_pgrp` 时先区分这两个“孤儿”。全局 init 退出会导致严重启动/运行失败，教学 PID 1 必须保持存活或正常关机。

## 回收实验的三张图

|阶段|用户程序动作|预期可观察|
|---|---|---|
|孩子存活|fork 后仍执行|/proc/child 存在，正常状态|
|孩子退出但未回收|waitid + WNOWAIT 返回|/proc/child/status 出现 Z|
|父亲完成回收|waitpid(child)|退出码 23；实验短窗口内 /proc/child 消失|

本实验检查 /proc 消失适合受控单次环境；繁忙系统 PID 快速复用会使纯路径存在性不再等于旧对象存在，需要更强身份（如 pidfd/开始时间）区分。这里不以同 PID 字符串证明对象永不复用。

检查题：孩子的内核栈何时能释放？至少要等 CPU 已离开它的执行栈，并满足栈引用规则；因此退出调用者自身不能把正在使用的栈立即回收到分配器。
