# 16 一页找回全貌，再用问题检验理解

## 八棵主树：箭头代表的关系已经标明

### 启动树（同栈调用 + 创建分叉）

```text
start_kernel
 ├ sched_init → init_idle(current, boot CPU)
 ├ pid_idr_init / anon_vma_init / fork_init / proc_caches_init
 └ arch_call_rest_init → rest_init
    ├ kernel_thread(kernel_init) → kernel_clone → copy_process [创建 PID 1]
    ├ kernel_thread(kthreadd) → kernel_clone → copy_process [创建 PID 2]
    ├ complete(kthreadd_done)
    └ schedule_preempt_disabled → cpu_startup_entry
PID 1: kernel_init → wait_for_completion → kernel_init_freeable → run_init_process
PID 2: kthreadd → 请求队列 → create_kthread
```

### 新任务树（失败时按 bad_fork 标签回滚）

```text
kernel_clone
 ├ copy_process
 │  ├ dup_task_struct → 分配描述符 + 内核栈
 │  ├ copy_creds / 限额与计数
 │  ├ sched_fork
 │  ├ copy_files / copy_fs / copy_sighand / copy_signal
 │  ├ copy_mm → CLONE_VM ? mmget : dup_mm
 │  ├ copy_namespaces / copy_io / copy_thread
 │  ├ alloc_pid / PID-TGID / 亲缘与可见性
 │  └ 返回新 task
 ├ trace_sched_process_fork
 ├ get_task_pid / pid_vnr
 ├ wake_up_new_task
 └ 可选 wait_for_vfork_done → 返回给父调用者
```

### 内存树（常规私有小页）

```text
copy_mm → dup_mm → mm_init + dup_mmap
 dup_mmap → 新 VMA / anon_vma 等 → copy_page_range
 copy_page_range → 各级 page range → copy_pte_range → copy_present_pte
 写保护双方 PTE，共享物理数据页（普通分支）
用户写 → do_user_addr_fault → handle_mm_fault → __handle_mm_fault
 → handle_pte_fault → do_wp_page → wp_page_copy / wp_page_reuse
```

### exec 树（替换当前任务映像）

```text
execve → do_execve → do_execveat_common → bprm_execve
 → exec_binprm → search_binary_handler → load_elf_binary
   ├ begin_new_exec → de_thread / unshare_files / exec_mmap / CLOEXEC
   ├ setup_arg_pages / PT_LOAD 映射 / 解释器 / BSS
   ├ create_elf_tables
   └ START_THREAD → start_thread → 返回用户执行新入口
```

### 调度树（选择与切换分开）

```text
阻塞 schedule / 返回用户态的重调度 / 合适抢占点
 → __schedule → pick_next_task → 调度类选择
 → prev != next 时 context_switch
    ├ switch_mm_irqs_off 或借用 active_mm
    ├ switch_to → __switch_to_asm → __switch_to
    └ finish_task_switch
新 task 第一次切入 → ret_from_fork → schedule_tail → 用户返回或内核入口
```

### 睡眠唤醒树（跨执行流因果）

```text
任务 A: 条件不满足 → 准备等待 → schedule → 停止占 CPU
任务 B/中断等: 更新条件 → wake_up → try_to_wake_up → A 可运行
未来选择 A → A 原栈恢复 → 重查条件 → 完成等待
```

### 内核线程树（请求者与创建者分开）

```text
请求者 kthread_create → __kthread_create_on_node → 队列 → 唤醒 kthreadd
kthreadd → create_kthread → kernel_thread(kthread, create,...)
新线程 kthread → 完成创建通知 → 等待启动 → threadfn → do_exit
请求者 kthread_run = 创建 + wake_up_process
```

### 退出回收树（孩子与父亲分开）

```text
孩子 do_exit → exit_mm / exit_files / exit_fs / exit_notify
 → do_task_dead → __schedule → 后继 task 收尾
父亲 wait4/waitid → do_wait → wait_task_zombie → release_task
最后引用/RCU 条件满足 → 结构存储最终回收
```

这些树是关键路径索引，不是编译器生成的穷尽调用图。安全、审计、cgroup、perf、锁、错误分支未在每张树重复；需要全函数请看下一章源码摘录。

## 24 道自测与答案要点

|题目|答案要点|
|---|---|
|1 谁 fork 了 PID 0？|它是静态 init_task，非普通 fork 产物|
|2 pid/tgid 没显式初始化为什么为零？|静态对象未指定字段按零初始化|
|3 proc_caches_init 只与 /proc 有关吗？|不是，含 mm/VMA/信号/文件等资源缓存|
|4 PID 1 等待点在哪？|kernel_init 开头的 wait_for_completion|
|5 kernel_thread 的函数参数在哪？|本版 kernel_clone_args.stack，arg 在 stack_size|
|6 PID 1 什么时候获得用户 mm？|执行内核 exec 装载并安装新 mm|
|7 task->mm=NULL 是否无任何页表？|不是，active_mm/内核映射仍有作用|
|8 fork 是否马上复制所有数据页？|普通私有页多先 COW，且有特殊映射例外|
|9 父亲 PTE 为什么也只读？|防止父写共享页破坏孩子快照|
|10 PTE 只读但 VM_WRITE 为真是否矛盾？|逻辑可写与暂时硬件写保护分层|
|11 do_wp_page 是否一定分配复制？|有独占复用/共享映射等分支|
|12 thread.sp 是用户栈吗？|不是，是切换用内核栈指针|
|13 子 fork 返回 0 在哪里构造？|copy_thread 设置 childregs->ax=0|
|14 子任务第一次去哪？|预制 ret_from_fork，随后 schedule_tail|
|15 exec 为什么不用重新分 PID？|替换已有任务映像；多线程 de_thread 有 TID 例外|
|16 ELF 直接调用 main 吗？|进入 ELF/解释器入口，经运行库才到 main|
|17 两线程共享 mm 是否共享内核栈？|不共享，每 task 有独立栈|
|18 fork 后 fd 偏移为何共享？|独立 fd 表仍引用同一个 struct file|
|19 vfork 父等新程序执行完吗？|等孩子释放旧 VM 使用，常在 exec/exit 时完成|
|20 TASK_RUNNING 是否肯定 on CPU？|包括可运行排队任务|
|21 每次 schedule 都 switch 吗？|prev==next 时无任务切换|
|22 同 mm 切换是否一定刷新全部 TLB？|不一定，x86 有同 mm/PCID 等优化|
|23 zombie 是否保留完整用户内存？|通常已释放使用引用与多数资源，保留可收集信息|
|24 wait 应按 current==子PID 过滤吗？|父执行 wait，回收按参数孩子 PID 过滤|

## 小毕业项目：从零口述一次运行

选一个只包含 fork、exec、wait 的用户程序。自己画出：父 task/子 task；fork 前后两个 mm；copy_thread 的两个栈指针；孩子第一次 ret_from_fork；exec 新 mm；一次 read 等待与唤醒；退出 mm_users 变化；zombie 到回收。每个箭头旁边写一个源码入口、一个字段变化和一个可观测方法。

如果你只能背 fork→copy_process，而说不出 p 什么时候有 PID、什么时候可能跑起来、什么时候旧指针可能失效，回第 05 章。如果你把 COW 与线程共享混在一起，回第 07/09 章。如果你认为 switch 后还是 A 的栈，回第 11 章。
