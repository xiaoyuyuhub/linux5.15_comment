# 03 匿名 mmap：从虚拟地址到物理页和 PTE

本章是拆分对照课，主角是 `01_anon_lazy`。第一次请先跟《00 统一大程序调试主线》运行 `00_memory_tour mmap`；掌握主链后，再用这个四页小程序做稀疏触页和 `MADV_DONTNEED` 扩展练习。

## 1. 先只跑，不开 GDB

```sh
/mnt/mm/bin/01_anon_lazy
```

每个 CHECKPOINT 用观察终端执行：

```sh
/mnt/mm/mm-observe PID
```

预期状态不是死板数值，而是下面的关系：

| 阶段 | 动作已完成 | VMA | 目标页可能状态 |
|---|---|---|---|
| A0 | 程序启动 | 目标 VMA 不存在 | 无目标页 |
| A1 | mmap 返回 | 四页区间合法、RW/private | 通常 `0000` |
| A2 | 只读第 0 页 | VMA 不变 | 第 0 页可驻留为共享只读零页 |
| A3 | 写第 1 页 | VMA 不变 | 第 1 页有私有匿名页 |
| A4 | 写第 3 页 | VMA 不变 | 第 2 页仍可未驻留，物理页不要求连续 |
| A5 | `MADV_DONTNEED` 第 1 页 | VMA 仍在 | 第 1 页内容被丢弃；再读应为零 |
| A6 | munmap | 目标 VMA 消失 | 旧地址失效 |

`mincore` 只回答驻留位，不直接告诉你 PFN、独占关系或 dirty 状态。第一次只读显示 `1` 也不能说“为此进程分配了一页私有 RAM”。

## 2. 捕获建立 VMA

以 `run.sh --gdb` 启动，在 guest 让程序停于 A0。GDB：

```gdb
lab-mmap
info breakpoints
continue
```

回主终端按 Enter。不同符号/优化下不一定每一层都形成独立栈帧，核心路径是：

```text
__x64_sys_mmap
→ ksys_mmap_pgoff
→ vm_mmap_pgoff
→ do_mmap
   → get_unmapped_area
   → mmap_region
```

在 `do_mmap` 可看：

```gdb
info args
p/x addr
p len
p/x prot
p/x flags
bt 8
```

`addr=0` 是没有固定提示，让内核选地址；返回后记录程序实际 `BASE`。一次 mmap 可能与兼容的相邻 VMA 合并，因此 `/proc/PID/maps` 不保证恰好出现一条长度四页的新行，必须判断哪一行覆盖 `[BASE, BASE+length)`。

## 3. 第一次只读：共享零页分支

在 A1 抄下 BASE，例如 `0x7f...000`。GDB 删除 mmap 高频断点，然后：

```gdb
delete breakpoints
lab-fault 0x实际BASE
continue
```

按 Enter 执行只读。命中 `handle_mm_fault` 后：

```gdb
p/x address
p/x vma->vm_start
p/x vma->vm_end
p/x vma->vm_flags
set $target_mm = vma->vm_mm
bt 8
```

x86 用户态页故障外层主线：

```text
asm_exc_page_fault
→ exc_page_fault
→ handle_page_fault
→ do_user_addr_fault
→ handle_mm_fault
→ __handle_mm_fault
→ handle_pte_fault
→ do_anonymous_page
```

首次匿名只读可以安装特殊共享 zero page 的只读 PTE。它省去为全零内容创建一张私有数据页；稍后写该页时会触发写保护/COW 类处理。

## 4. 第一次写：真正申请私有匿名页

A2 后目标写地址不是 BASE，而是 `BASE + page_size`。在当前实验 page size 为 4096 时：

```gdb
delete breakpoints
set $write_addr = 0x实际BASE + 4096
break handle_mm_fault if address == $write_addr
continue
```

命中后确认 VMA/mm，再深入：

```gdb
disable 1
break do_anonymous_page
continue
p/x vmf->address
p/x vmf->flags
```

匿名首次写主线：

```text
do_anonymous_page
→ alloc_zeroed_user_highpage_movable
→ alloc_pages_vma
→ __alloc_pages
→ get_page_from_freelist
→ rmqueue
→ PCP 或 buddy
→ mk_pte
→ set_pte_at
```

分配物理页和写 PTE 是两件事：`struct page *` 表示 PFN 的内核描述对象，PTE 才把当前 mm 的虚拟页指向 PFN。页表页自身也可能触发内核页分配，所以无条件断 `__alloc_pages` 会看到不止一个页。

若要进 buddy，只在已经停住目标 fault 后执行：

```gdb
lab-buddy
continue
```

`__alloc_pages/get_page_from_freelist/rmqueue` 都是全局高频点；每命中一次都核对调用栈是否仍来自目标 `do_anonymous_page`。PCP 有库存时，order-0 请求可能不需要直接从 buddy 拆块；PCP 补货时才批量碰 buddy。这两种结果都正确。

## 5. 稀疏触页、丢弃和解除映射

A3 到 A4 写第 3 页，中间第 2 页仍可没有私有数据页。这证明虚拟区间连续不等于所有页已驻留，更不等于物理 PFN 连续。

`MADV_DONTNEED` 对匿名私有页表示调用者不再需要现有内容。VMA 不必消失，但相应 PTE/页可以被撤销和释放；未来再访问时内容按匿名映射语义重新成为零。

A5 后跟 munmap：

```gdb
delete breakpoints
lab-unmap 0x实际BASE
continue
```

主线：

```text
__x64_sys_munmap
→ __do_munmap
→ unmap_region
→ unmap_vmas
→ zap_pte_range
→ mmu_gather / TLB flush / page release
```

`munmap` 返回时区间已不再合法，但物理页释放的内部批处理、TLB 安全点和 PCP/buddy 路径不能简化成“这一行立即把每一页直接插回 free_area”。

## 6. 本轮验收

拿一轮真实记录回答：BASE 是多少？A1 的 maps 覆盖区间是哪一行？第一次读和第一次写各命中哪个 fault 分支？`vma->vm_mm` 是多少？写第 3 页时为何第 2 页仍可不驻留？munmap 后哪条 maps 行消失？没有这六项证据，就不要把“我看过调用树”当成“我已经验证过调用链”。
