\doxysubsection{Detailed Description}
struct \mbox{\hyperlink{structieee80211__tx__rate}{ieee80211\+\_\+tx\+\_\+rate}} -\/ rate selection/status

@idx\+: rate index to attempt to send with @flags\+: rate control flags (\&enum mac80211\+\_\+rate\+\_\+control\+\_\+flags) @count\+: number of tries in this rate before going to the next rate

A value of -\/1 for @idx indicates an invalid rate and, if used in an array of retry rates, that no more rates should be tried.

When used for transmit status reporting, the driver should always report the rate along with the flags it used.

\&struct \mbox{\hyperlink{structieee80211__tx__info}{ieee80211\+\_\+tx\+\_\+info}} \mbox{\hyperlink{protocolcontains-p}{contains}} an array of these structs in the control information, and it will be filled by the rate control algorithm according to what should be sent. For example, if this array \mbox{\hyperlink{protocolcontains-p}{contains}}, in the format \{ $<$idx$>$, $<$count$>$ \} the information\+:\+:

\{ 3, 2 \}, \{ 2, 2 \}, \{ 1, 4 \}, \{ -\/1, 0 \}, \{ -\/1, 0 \}

then this means that the frame should be transmitted up to twice at rate 3, up to twice at rate 2, and up to four times at rate 1 if it doesn\textquotesingle{}t get acknowledged. Say it gets acknowledged by the peer after the fifth attempt, the status information should then contain\+:\+:

\{ 3, 2 \}, \{ 2, 2 \}, \{ 1, 1 \}, \{ -\/1, 0 \} ...

since it was transmitted twice at rate 3, twice at rate 2 and once at rate 1 after which we received an acknowledgement.
