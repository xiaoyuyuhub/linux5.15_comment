E\+V\+I\+O\+C\+G\+M\+A\+SK -\/ Retrieve current event mask

This ioctl allows user to retrieve the current event mask for specific event type. \mbox{\hyperlink{classThe}{The}} argument must be of type \char`\"{}struct input\+\_\+mask\char`\"{} and specifies the event type to query, the address of the receive buffer and the size of the receive buffer.

\mbox{\hyperlink{classThe}{The}} event mask is a per-\/client mask that specifies which events are forwarded to the client. Each event code is represented by a single bit in the event mask. If the bit is set, the event is passed to the client normally. Otherwise, the event is filtered and will never be queued on the client\textquotesingle{}s receive buffer.

Event masks do not affect global state of the input device. They only affect the file descriptor they are applied to.

\mbox{\hyperlink{classThe}{The}} default event mask for a client has all bits set, i.\+e. all events are forwarded to the client. If the kernel is queried for an unknown event type or if the receive buffer is larger than the number of event codes known to the kernel, the kernel returns all zeroes for those codes.

At maximum, codes\+\_\+size bytes are copied.

This ioctl may fail with E\+N\+O\+D\+EV in case the file is revoked, E\+F\+A\+U\+LT if the receive-\/buffer points to invalid memory, or E\+I\+N\+V\+AL if the kernel does not implement the ioctl. \mbox{\Hypertarget{uapi_2linux_2input_8h_a5de6868909e4a77e5391bb3a9efd7296}\label{uapi_2linux_2input_8h_a5de6868909e4a77e5391bb3a9efd7296}}

E\+V\+I\+O\+C\+S\+M\+A\+SK -\/ Set event mask

This ioctl is the counterpart to E\+V\+I\+O\+C\+G\+M\+A\+SK. Instead of receiving the current event mask, this changes the client\textquotesingle{}s event mask for a specific type. See E\+V\+I\+O\+C\+G\+M\+A\+SK for a description of event-\/masks and the argument-\/type.

This ioctl provides full forward compatibility. If the passed event type is unknown to the kernel, or if the number of event codes specified in the mask is bigger than what is known to the kernel, the ioctl is still accepted and applied.
