@atomic\+\_\+async\+\_\+update\+:

Drivers should set this function pointer to perform asynchronous updates of planes, that is, jump ahead of the currently queued state and update the plane. Here async means \char`\"{}not vblank
synchronized\char`\"{}.

This hook is called by \mbox{\hyperlink{drm__atomic__helper_8h_abf7824e4b45ac09ab6997127525f10a7}{drm\+\_\+atomic\+\_\+helper\+\_\+async\+\_\+commit()}}.

An async update will happen on legacy cursor updates. An async update won\textquotesingle{}t happen if there is an outstanding commit modifying the same plane.

When doing async\+\_\+update drivers shouldn\textquotesingle{}t replace the \&\mbox{\hyperlink{structdrm__plane__state}{drm\+\_\+plane\+\_\+state}} but update the current one with the new plane configurations in the new plane\+\_\+state.

Drivers should also swap the framebuffers between current plane state (\&\mbox{\hyperlink{structdrm__plane_ad86f68a9e3261f80c79330279611c70b}{drm\+\_\+plane.\+state}}) and new\+\_\+state. This is required since cleanup for async commits is performed on the new state, rather than old state like for traditional commits. Since we want to give up the reference on the current (old) fb instead of our brand new one, swap them in the driver during the async commit.

F\+I\+X\+ME\+:
\begin{DoxyItemize}
\item It only works for single plane updates
\item Async Pageflips are not supported yet
\item Some hw might still scan out the old buffer until the next vblank, however we let go of the fb references as soon as we run this hook. For now drivers must implement their own workers for deferring if needed, until a common solution is created. 
\end{DoxyItemize}\mbox{\Hypertarget{structdrm__plane__helper__funcs_a5ca6793c42d8383f4d37803f50de15f4}\label{structdrm__plane__helper__funcs_a5ca6793c42d8383f4d37803f50de15f4}}

@atomic\+\_\+check\+:

Drivers should check plane specific constraints in this hook.

When using \mbox{\hyperlink{drm__atomic__helper_8h_aae49b77f48f0c74bf8e44d9c7980f7b8}{drm\+\_\+atomic\+\_\+helper\+\_\+check\+\_\+planes()}} plane\textquotesingle{}s @atomic\+\_\+check hooks are called before the ones for C\+R\+T\+Cs, which allows drivers to request shared resources that the C\+R\+TC controls here. For more complicated dependencies the driver can call the provided check helpers multiple times until the computed state has a final configuration and everything has been checked.

This function is also allowed to inspect any other object\textquotesingle{}s state and can add more state objects to the atomic commit if needed. Care must be taken though to ensure that state check and compute functions for these added states are all called, and derived state in other objects all updated. Again the recommendation is to just call check helpers until a maximal configuration is reached.

This callback is used by the atomic modeset helpers and by the transitional plane helpers, but it is optional.

N\+O\+TE\+:

This function is called in the check phase of an atomic update. \mbox{\hyperlink{classThe}{The}} driver is not allowed to change anything outside of the \&\mbox{\hyperlink{structdrm__atomic__state}{drm\+\_\+atomic\+\_\+state}} update tracking structure.

R\+E\+T\+U\+R\+NS\+:

0 on success, -\/E\+I\+N\+V\+AL if the state or the transition can\textquotesingle{}t be supported, -\/E\+N\+O\+M\+EM on memory allocation failure and -\/E\+D\+E\+A\+D\+LK if an attempt to obtain another state object ran into a \&\mbox{\hyperlink{structdrm__modeset__lock}{drm\+\_\+modeset\+\_\+lock}} deadlock. \mbox{\Hypertarget{structdrm__plane__helper__funcs_a43eb82cdbb4cfca89dc5380f651f0427}\label{structdrm__plane__helper__funcs_a43eb82cdbb4cfca89dc5380f651f0427}}

@prepare\+\_\+fb\+:

This hook is to prepare a framebuffer for scanout by e.\+g. pinning its backing storage or relocating it into a contiguous block of V\+R\+AM. Other possible preparatory work includes flushing caches.

This function must not block for outstanding rendering, since it is called in the context of the atomic I\+O\+C\+TL even for async commits to be able to return any errors to userspace. Instead the recommended way is to fill out the \&\mbox{\hyperlink{structdrm__plane__state_af70132cfd54b65d0fddba5153f56f87b}{drm\+\_\+plane\+\_\+state.\+fence}} of the passed-\/in \&\mbox{\hyperlink{structdrm__plane__state}{drm\+\_\+plane\+\_\+state}}. If the driver doesn\textquotesingle{}t support native fences then equivalent functionality should be implemented through private members in the plane structure.

For G\+EM drivers who neither have a @prepare\+\_\+fb nor @cleanup\+\_\+fb hook set \mbox{\hyperlink{drm__gem__atomic__helper_8h_a325e067a7d838bf1bbf30f5fe27fafcf}{drm\+\_\+gem\+\_\+plane\+\_\+helper\+\_\+prepare\+\_\+fb()}} is called automatically to implement this. Other drivers which need additional plane processing can call \mbox{\hyperlink{drm__gem__atomic__helper_8h_a325e067a7d838bf1bbf30f5fe27fafcf}{drm\+\_\+gem\+\_\+plane\+\_\+helper\+\_\+prepare\+\_\+fb()}} from their @prepare\+\_\+fb hook.

\mbox{\hyperlink{classThe}{The}} helpers will call @cleanup\+\_\+fb with matching arguments for every successful call to this hook.

This callback is used by the atomic modeset helpers and by the transitional plane helpers, but it is optional.

R\+E\+T\+U\+R\+NS\+:

0 on success or one of the following negative error codes allowed by the \&\mbox{\hyperlink{structdrm__mode__config__funcs_a32f809652a60b1764864e36130b4ca20}{drm\+\_\+mode\+\_\+config\+\_\+funcs.\+atomic\+\_\+commit}} vfunc. When using helpers this callback is the only one which can fail an atomic commit, everything else must complete successfully.
