walk\+\_\+page\+\_\+mapping -\/ walk all memory areas mapped into a struct \mbox{\hyperlink{structaddress__space}{address\+\_\+space}}. @mapping\+: Pointer to the struct \mbox{\hyperlink{structaddress__space}{address\+\_\+space}} @first\+\_\+index\+: First page offset in the \mbox{\hyperlink{structaddress__space}{address\+\_\+space}} @nr\+: Number of incremental page offsets to cover @ops\+: operation to call during the walk \+: private data for callbacks\textquotesingle{} usage

This function walks all memory areas mapped into a struct \mbox{\hyperlink{structaddress__space}{address\+\_\+space}}. \mbox{\hyperlink{classThe}{The}} walk is limited to only the given page-\/size index range, but if the index boundaries cross a huge page-\/table entry, that entry will be included.

Also see \mbox{\hyperlink{pagewalk_8h_ae5654e607e3e2bcecb29fc8ed134eb08}{walk\+\_\+page\+\_\+range()}} for additional information.

Locking\+: This function can\textquotesingle{}t require that the struct \mbox{\hyperlink{structmm__struct_a710618a8f9090c721fd35e42633ed7a4}{mm\+\_\+struct\+::mmap\+\_\+lock}} is held, since @mapping may be mapped by multiple processes. Instead @mapping-\/$>$i\+\_\+mmap\+\_\+rwsem must be held. This might have implications in the callbacks, and it\textquotesingle{}s up tho the caller to ensure that the struct \mbox{\hyperlink{structmm__struct_a710618a8f9090c721fd35e42633ed7a4}{mm\+\_\+struct\+::mmap\+\_\+lock}} is not needed.

Also this means that a caller can\textquotesingle{}t rely on the struct \mbox{\hyperlink{structvm__area__struct_a01c667f4f7db4efaa1b5fbd3be45ea0a}{vm\+\_\+area\+\_\+struct\+::vm\+\_\+flags}} to be constant across a call, except for immutable flags. Callers requiring this shouldn\textquotesingle{}t use this function.

walk\+\_\+page\+\_\+range -\/ walk page table with caller specific callbacks @mm\+: \mbox{\hyperlink{structmm__struct}{mm\+\_\+struct}} representing the target process of page table walk @start\+: start address of the virtual address range @end\+: end address of the virtual address range @ops\+: operation to call during the walk \+: private data for callbacks\textquotesingle{} usage

Recursively walk the page table tree of the process represented by @mm within the virtual address range \mbox{[}@start, @end). During walking, we can do some caller-\/specific works for each entry, by setting up pmd\+\_\+entry(), pte\+\_\+entry(), and/or hugetlb\+\_\+entry(). If you don\textquotesingle{}t set up for some of these callbacks, the associated entries/pages are just ignored. \mbox{\hyperlink{classThe}{The}} return values of these callbacks are commonly defined like below\+:


\begin{DoxyItemize}
\item 0 \+: succeeded to handle the current entry, and if you don\textquotesingle{}t reach the end address yet, continue to walk.
\item $>$0 \+: succeeded to handle the current entry, and return to the caller with caller specific value.
\item $<$0 \+: failed to handle the current entry, and return to the caller with error code.
\end{DoxyItemize}

Before starting to walk page table, some callers want to check whether they really want to walk over the current vma, typically by checking its vm\+\_\+flags. \mbox{\hyperlink{pagewalk_8c_ab4f6e69d8d47614be6a5b4cc4f730bd2}{walk\+\_\+page\+\_\+test()}} and @ops-\/$>$test\+\_\+walk() are used for this purpose.

If operations need to be staged before and committed after a vma is walked, there are two callbacks, pre\+\_\+vma() and post\+\_\+vma(). Note that post\+\_\+vma(), since it is intended to handle commit-\/type operations, can\textquotesingle{}t return any errors.

struct mm\+\_\+walk keeps current values of some common data like vma and pmd, which are useful for the access from callbacks. If you want to pass some caller-\/specific data to callbacks,should be helpful.
