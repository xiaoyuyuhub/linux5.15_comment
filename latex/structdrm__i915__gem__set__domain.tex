\doxysubsection{Detailed Description}
struct \mbox{\hyperlink{structdrm__i915__gem__set__domain}{drm\+\_\+i915\+\_\+gem\+\_\+set\+\_\+domain}} -\/ Adjust the objects write or read domain, in preparation for accessing the pages via some C\+PU domain.

Specifying a new write or read domain will flush the object out of the previous domain(if required), before then updating the objects domain tracking with the new domain.

Note this might involve waiting for the object first if it is still active on the G\+PU.

Supported values for @read\+\_\+domains and @write\+\_\+domain\+:


\begin{DoxyItemize}
\item I915\+\_\+\+G\+E\+M\+\_\+\+D\+O\+M\+A\+I\+N\+\_\+\+WC\+: Uncached write-\/combined domain
\item I915\+\_\+\+G\+E\+M\+\_\+\+D\+O\+M\+A\+I\+N\+\_\+\+C\+PU\+: C\+PU cache domain
\item I915\+\_\+\+G\+E\+M\+\_\+\+D\+O\+M\+A\+I\+N\+\_\+\+G\+TT\+: Mappable aperture domain
\end{DoxyItemize}

All other domains are rejected.

Note that for discrete, starting from D\+G1, this is no longer supported, and is instead rejected. On such platforms the C\+PU domain is effectively static, where we also only support a single \&\mbox{\hyperlink{structdrm__i915__gem__mmap__offset}{drm\+\_\+i915\+\_\+gem\+\_\+mmap\+\_\+offset}} cache mode, which can\textquotesingle{}t be set explicitly and instead depends on the object placements, as per the below.

Implicit caching rules, starting from D\+G1\+:


\begin{DoxyItemize}
\item If any of the object placements (see \&\mbox{\hyperlink{structdrm__i915__gem__create__ext__memory__regions}{drm\+\_\+i915\+\_\+gem\+\_\+create\+\_\+ext\+\_\+memory\+\_\+regions}}) contain I915\+\_\+\+M\+E\+M\+O\+R\+Y\+\_\+\+C\+L\+A\+S\+S\+\_\+\+D\+E\+V\+I\+CE then the object will be allocated and mapped as write-\/combined only.
\item Everything else is always allocated and mapped as write-\/back, with the guarantee that everything is also coherent with the G\+PU.
\end{DoxyItemize}

Note that this is likely to change in the future again, where we might need more flexibility on future devices, so making this all explicit as part of a new \&\mbox{\hyperlink{structdrm__i915__gem__create__ext}{drm\+\_\+i915\+\_\+gem\+\_\+create\+\_\+ext}} extension is probable.
