{\footnotesize\ttfamily \#define B\+M\+\_\+\+E\+N\+D\+\_\+\+O\+F\+\_\+\+M\+AP~($\sim$0\+UL)}

Data types related to memory bitmaps.

Memory bitmap is a structure consisting of many linked lists of objects. \mbox{\hyperlink{classThe}{The}} main list\textquotesingle{}s elements are of type struct zone\+\_\+bitmap and each of them corresponds to one zone. For each zone bitmap object there is a list of objects of type struct bm\+\_\+block that represent each blocks of bitmap in which information is stored.

struct \mbox{\hyperlink{structmemory__bitmap}{memory\+\_\+bitmap}} \mbox{\hyperlink{protocolcontains-p}{contains}} a pointer to the main list of zone bitmap objects, a struct \mbox{\hyperlink{structbm__position}{bm\+\_\+position}} used for browsing the bitmap, and a pointer to the list of pages used for allocating all of the zone bitmap objects and bitmap block objects.

N\+O\+TE\+: It has to be possible to lay out the bitmap in memory using only allocations of order 0. Additionally, the bitmap is designed to work with arbitrary number of zones (this is over the top for now, but let\textquotesingle{}s avoid making unnecessary assumptions ;-\/).

struct zone\+\_\+bitmap \mbox{\hyperlink{protocolcontains-p}{contains}} a pointer to a list of bitmap block objects and a pointer to the bitmap block object that has been most recently used for setting bits. Additionally, it \mbox{\hyperlink{protocolcontains-p}{contains}} the P\+F\+Ns that correspond to the start and end of the represented zone.

struct bm\+\_\+block \mbox{\hyperlink{protocolcontains-p}{contains}} a pointer to the memory page in which information is stored (in the form of a block of bitmap) It also \mbox{\hyperlink{protocolcontains-p}{contains}} the pfns that correspond to the start and end of the represented memory area.

\mbox{\hyperlink{classThe}{The}} memory bitmap is organized as a radix tree to guarantee fast random access to the bits. There is one radix tree for each zone (as returned from create\+\_\+mem\+\_\+extents).

One radix tree is represented by one struct \mbox{\hyperlink{structmem__zone__bm__rtree}{mem\+\_\+zone\+\_\+bm\+\_\+rtree}}. There are two linked lists for the nodes of the tree, one for the inner nodes and one for the leave nodes. \mbox{\hyperlink{classThe}{The}} linked leave nodes are used for fast linear access of the memory bitmap.

hibernate\+\_\+preallocate\+\_\+memory -\/ Preallocate memory for hibernation image.

To create a hibernation image it is necessary to make a copy of every page frame in use. We also need a number of page frames to be free during hibernation for allocations made while saving the image and for device drivers, in case they need to allocate memory from their hibernation callbacks (these two numbers are given by P\+A\+G\+E\+S\+\_\+\+F\+O\+R\+\_\+\+IO (which is a rough estimate) and reserved\+\_\+size divided by P\+A\+G\+E\+\_\+\+S\+I\+ZE (which is tunable through /sys/power/reserved\+\_\+size, respectively). To make this happen, we compute the total number of available page frames and allocate at least

(\mbox{[}page frames total\mbox{]} + P\+A\+G\+E\+S\+\_\+\+F\+O\+R\+\_\+\+IO + \mbox{[}metadata pages\mbox{]}) / 2
