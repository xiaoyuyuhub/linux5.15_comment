\doxysubsection{Detailed Description}
struct \mbox{\hyperlink{structusb__gadget__driver}{usb\+\_\+gadget\+\_\+driver}} -\/ driver for usb gadget devices @function\+: String describing the gadget\textquotesingle{}s function @max\+\_\+speed\+: Highest speed the driver handles. @setup\+: Invoked for ep0 control requests that aren\textquotesingle{}t handled by the hardware level driver. Most calls must be handled by the gadget driver, including descriptor and configuration management. \mbox{\hyperlink{classThe}{The}} 16 bit members of the setup data are in U\+SB byte order. Called in\+\_\+interrupt; this may not sleep. Driver queues a response to ep0, or returns negative to stall. @disconnect\+: Invoked after all transfers have been stopped, when the host is disconnected. May be called in\+\_\+interrupt; this may not sleep. Some devices can\textquotesingle{}t detect disconnect, so this might not be called except as part of controller shutdown. @bind\+: the driver\textquotesingle{}s bind callback @unbind\+: Invoked when the driver is unbound from a gadget, usually from rmmod (after a disconnect is reported). Called in a context that permits sleeping. @suspend\+: Invoked on U\+SB suspend. May be called in\+\_\+interrupt. @resume\+: Invoked on U\+SB resume. May be called in\+\_\+interrupt. @reset\+: Invoked on U\+SB bus reset. It is mandatory for all gadget drivers and should be called in\+\_\+interrupt. @driver\+: Driver model state for this driver. @udc\+\_\+name\+: A name of U\+DC this driver should be bound to. If udc\+\_\+name is N\+U\+LL, this driver will be bound to any available U\+DC. @pending\+: U\+DC core private data used for deferred probe of this driver. @match\+\_\+existing\+\_\+only\+: If udc is not found, return an error and don\textquotesingle{}t add this gadget driver to list of pending driver

Devices are disabled till a gadget driver successfully \mbox{\hyperlink{structusb__gadget__driver_a6e1f6635da3bb534aac82ad9fa8a3a41}{bind()}}s, which means the driver will handle \mbox{\hyperlink{structusb__gadget__driver_a2b8ac37b7419e87e089174dbf4f21b70}{setup()}} requests needed to enumerate (and meet \char`\"{}chapter 9\char`\"{} requirements) then do some useful work.

If gadget-\/$>$is\+\_\+otg is true, the gadget driver must provide an O\+TG descriptor during enumeration, or else fail the \mbox{\hyperlink{structusb__gadget__driver_a6e1f6635da3bb534aac82ad9fa8a3a41}{bind()}} call. In such cases, no U\+SB traffic may flow until both \mbox{\hyperlink{structusb__gadget__driver_a6e1f6635da3bb534aac82ad9fa8a3a41}{bind()}} returns without having called \mbox{\hyperlink{gadget_8h_a2ccb825d73aeb99f8279e5bead4b2210}{usb\+\_\+gadget\+\_\+disconnect()}}, and the U\+SB host stack has initialized.

Drivers use hardware-\/specific knowledge to configure the usb hardware. endpoint addressing is only one of several hardware characteristics that are in descriptors the ep0 implementation returns from \mbox{\hyperlink{structusb__gadget__driver_a2b8ac37b7419e87e089174dbf4f21b70}{setup()}} calls.

Except for ep0 implementation, most driver code shouldn\textquotesingle{}t need change to run on top of different usb controllers. It\textquotesingle{}ll use endpoints set up by that ep0 implementation.

\mbox{\hyperlink{classThe}{The}} usb controller driver handles a few standard usb requests. Those include set\+\_\+address, and feature flags for devices, interfaces, and endpoints (the get\+\_\+status, set\+\_\+feature, and clear\+\_\+feature requests).

Accordingly, the driver\textquotesingle{}s \mbox{\hyperlink{structusb__gadget__driver_a2b8ac37b7419e87e089174dbf4f21b70}{setup()}} callback must always implement all get\+\_\+descriptor requests, returning at least a device descriptor and a configuration descriptor. Drivers must make sure the endpoint descriptors match any hardware constraints. Some hardware also constrains other descriptors. (\mbox{\hyperlink{classThe}{The}} pxa250 allows only configurations 1, 2, or 3).

\mbox{\hyperlink{classThe}{The}} driver\textquotesingle{}s \mbox{\hyperlink{structusb__gadget__driver_a2b8ac37b7419e87e089174dbf4f21b70}{setup()}} callback must also implement set\+\_\+configuration, and should also implement set\+\_\+interface, get\+\_\+configuration, and get\+\_\+interface. Setting a configuration (or interface) is where endpoints should be activated or (config 0) shut down.

(Note that only the default control endpoint is supported. Neither hosts nor devices generally support control traffic except to ep0.)

Most devices will ignore U\+SB suspend/resume operations, and so will not provide those callbacks. However, some may need to change modes when the host is not longer directing those activities. For example, local controls (buttons, dials, etc) may need to be re-\/enabled since the (remote) host can\textquotesingle{}t do that any longer; or an error state might be cleared, to make the device behave identically whether or not power is maintained.
