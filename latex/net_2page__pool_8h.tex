D\+OC\+: \mbox{\hyperlink{structpage__pool}{page\+\_\+pool}} allocator

This \mbox{\hyperlink{structpage__pool}{page\+\_\+pool}} allocator is optimized for the X\+DP mode that uses one-\/frame-\/per-\/page, but have fallbacks that act like the regular page allocator A\+P\+Is.

Basic use involve replacing \mbox{\hyperlink{mempolicy_8c_add7a36e6a0c552051c3453df754b9c7b}{alloc\+\_\+pages()}} calls with the \mbox{\hyperlink{net_2page__pool_8h_a9df5c2562373134a620abaf7d6ed4845}{page\+\_\+pool\+\_\+alloc\+\_\+pages()}} call. Drivers should likely use \mbox{\hyperlink{net_2page__pool_8h_a75d2740bac3cd6e8f16ff9d827d92ac1}{page\+\_\+pool\+\_\+dev\+\_\+alloc\+\_\+pages()}} replacing dev\+\_\+alloc\+\_\+pages().

A\+PI keeps track of in-\/flight pages, in-\/order to let A\+PI user know when it is safe to dealloactor \mbox{\hyperlink{structpage__pool}{page\+\_\+pool}} object. Thus, A\+PI users must make sure to call \mbox{\hyperlink{net_2page__pool_8h_a4c481711141c86fff66ac0318eaccfff}{page\+\_\+pool\+\_\+release\+\_\+page()}} when a page is \char`\"{}leaving\char`\"{} the \mbox{\hyperlink{structpage__pool}{page\+\_\+pool}}. Or call \mbox{\hyperlink{net_2page__pool_8h_a80feb2bc24b3995bba7c08a93253220e}{page\+\_\+pool\+\_\+put\+\_\+page()}} where appropiate. For maintaining correct accounting.

A\+PI user must only call \mbox{\hyperlink{net_2page__pool_8h_a80feb2bc24b3995bba7c08a93253220e}{page\+\_\+pool\+\_\+put\+\_\+page()}} once on a page, as it will either recycle the page, or in case of elevated refcnt, it will release the D\+MA mapping and in-\/flight state accounting.
