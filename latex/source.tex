vm\+\_\+insert\+\_\+page -\/ insert single page into user vma @vma\+: user vma to map to @addr\+: target user address of this page

This allows drivers to insert individual pages they\textquotesingle{}ve allocated into a user vma.

\mbox{\hyperlink{classThe}{The}} page has to be a nice clean {\itshape individual} kernel allocation. If you allocate a compound page, you need to have marked it as such (\+\_\+\+\_\+\+G\+F\+P\+\_\+\+C\+O\+MP), or manually just split the page up yourself (see \mbox{\hyperlink{page__alloc_8c_abd23d9d1d47d00b0433cad037f8d4972}{split\+\_\+page()}}).

N\+O\+T\+E! Traditionally this was done with \char`\"{}remap\+\_\+pfn\+\_\+range()\char`\"{} which took an arbitrary page protection parameter. This doesn\textquotesingle{}t allow that. Your vma protection will have to be set up correctly, which means that if you want a shared writable mapping, you\textquotesingle{}d better ask for a shared writable mapping!

\mbox{\hyperlink{classThe}{The}} page does not need to be reserved.

Usually this function is called from f\+\_\+op-\/$>$mmap() handler under mm-\/$>$mmap\+\_\+lock write-\/lock, so it can change vma-\/$>$vm\+\_\+flags. Caller must set V\+M\+\_\+\+M\+I\+X\+E\+D\+M\+AP on vma if it wants to call this function from other places, for example from page-\/fault handler.

Return\+: \%0 on success, negative error code otherwise.
