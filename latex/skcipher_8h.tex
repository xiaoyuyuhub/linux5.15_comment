D\+OC\+: Symmetric Key Cipher A\+PI

Symmetric key cipher A\+PI is used with the ciphers of type C\+R\+Y\+P\+T\+O\+\_\+\+A\+L\+G\+\_\+\+T\+Y\+P\+E\+\_\+\+S\+K\+C\+I\+P\+H\+ER (listed as type \char`\"{}skcipher\char`\"{} in /proc/crypto).

Asynchronous cipher operations imply that the function invocation for a cipher request returns immediately before the completion of the operation. \mbox{\hyperlink{classThe}{The}} cipher request is scheduled as a separate kernel thread and therefore load-\/balanced on the different C\+P\+Us via the process scheduler. To allow the kernel crypto A\+PI to inform the caller about the completion of a cipher request, the caller must provide a callback function. That function is invoked with the cipher handle when the request completes.

To support the asynchronous operation, additional information than just the cipher handle must be supplied to the kernel crypto A\+PI. That additional information is given by filling in the \mbox{\hyperlink{structskcipher__request}{skcipher\+\_\+request}} data structure.

For the symmetric key cipher A\+PI, the state is maintained with the tfm cipher handle. A single tfm can be used across multiple calls and in parallel. For asynchronous block cipher calls, context data supplied and only used by the caller can be referenced the request data structure in addition to the IV used for the cipher request. \mbox{\hyperlink{classThe}{The}} maintenance of such state information would be important for a crypto driver implementer to have, because when calling the callback function upon completion of the cipher operation, that callback function may need some information about which operation just finished if it invoked multiple in parallel.
