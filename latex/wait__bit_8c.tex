wake\+\_\+up\+\_\+bit -\/ wake up a waiter on a bit @word\+: the word being waited on, a kernel virtual address @bit\+: the bit of the word being waited on

There is a standard hashed waitqueue table for generic use. This is the part of the hashtable\textquotesingle{}s accessor A\+PI that wakes up waiters on a bit. For instance, if one were to have waiters on a bitflag, one would call \mbox{\hyperlink{wait__bit_8c_a836285f3a75a94d7d69a19c60d65df29}{wake\+\_\+up\+\_\+bit()}} after clearing the bit.

In order for this to function properly, as it uses waitqueue\+\_\+active() internally, some kind of memory barrier must be done prior to calling this. Typically, this will be \mbox{\hyperlink{include_2asm-generic_2barrier_8h_a60b18bcd5de2655b6d6b7d2059550afb}{smp\+\_\+mb\+\_\+\+\_\+after\+\_\+atomic()}}, but in some cases where bitflags are manipulated non-\/atomically under a lock, one may need to use a less regular barrier, such fs/inode.\+c\textquotesingle{}s \mbox{\hyperlink{include_2asm-generic_2barrier_8h_a27f506b47c1290294cff907d92c96da1}{smp\+\_\+mb()}}, because \mbox{\hyperlink{include_2linux_2spinlock_8h_a63e6a7103a25059cfea6908dffc740c0}{spin\+\_\+unlock()}} does not guarantee a memory barrier.
