@char\+\_\+per\+\_\+block\+:

Number of bytes per block (per plane), where blocks are defined as a rectangle of pixels which are stored next to each other in a byte aligned memory region. Together with @block\+\_\+w and @block\+\_\+h this is used to properly describe tiles in tiled formats or to describe groups of pixels in packed formats for which the memory needed for a single pixel is not byte aligned.

@cpp has been kept for historical reasons because there are a lot of places in drivers where it\textquotesingle{}s used. In drm core for generic code paths the preferred way is to use @char\+\_\+per\+\_\+block, \mbox{\hyperlink{drm_2drm__fourcc_8h_a59dafe9586ccad9b2b6c9ff1c816c354}{drm\+\_\+format\+\_\+info\+\_\+block\+\_\+width()}} and \mbox{\hyperlink{drm_2drm__fourcc_8h_a2a142ebc59d5d4c1bdaa1dbd3aeba9c7}{drm\+\_\+format\+\_\+info\+\_\+block\+\_\+height()}} which allows handling both block and non-\/block formats in the same way.

For formats that are intended to be used only with non-\/linear modifiers both @cpp and @char\+\_\+per\+\_\+block must be 0 in the generic format table. Drivers could supply accurate information from their drm\+\_\+mode\+\_\+config.\+get\+\_\+format\+\_\+info hook if they want the core to be validating the pitch. \mbox{\Hypertarget{structdrm__format__info_a1956a45d6398904e9f5377c6ab9aea93}\label{structdrm__format__info_a1956a45d6398904e9f5377c6ab9aea93}}
