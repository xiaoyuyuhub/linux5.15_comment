\doxysubsection{Detailed Description}
\mbox{\hyperlink{classThe}{The}} B\+P\+MP firmware includes a thermal framework. Drivers within the bpmp firmware register with the framework to provide thermal zones. Each thermal zone corresponds to an entity whose temperature can be measured. \mbox{\hyperlink{classThe}{The}} framework also has a notion of trip points. A trip point consists of a thermal zone id, a temperature, and a callback routine. \mbox{\hyperlink{classThe}{The}} framework invokes the callback when the zone hits the indicated temperature. \mbox{\hyperlink{classThe}{The}} B\+P\+MP firmware uses this thermal framework interally to implement various temperature-\/dependent functions.

Software on the C\+PU can use \mbox{\hyperlink{group__MRQ__Codes_ga1ae2e7acc9142340c84892200c4e53ec}{M\+R\+Q\+\_\+\+T\+H\+E\+R\+M\+AL}} (with payload \mbox{\hyperlink{structmrq__thermal__host__to__bpmp__request}{mrq\+\_\+thermal\+\_\+host\+\_\+to\+\_\+bpmp\+\_\+request}}) to interact with the B\+P\+MP thermal framework. \mbox{\hyperlink{classThe}{The}} C\+PU must It can query the number of supported zones, query zone temperatures, and set trip points.

When a trip point set by the C\+PU gets crossed, B\+P\+MP firmware issues an I\+PC to the C\+PU having \mbox{\hyperlink{structmrq__request_ae1e703f5c6485ac5122f70a6a0590b97}{mrq\+\_\+request\+::mrq}} = \mbox{\hyperlink{group__MRQ__Codes_ga1ae2e7acc9142340c84892200c4e53ec}{M\+R\+Q\+\_\+\+T\+H\+E\+R\+M\+AL}} and a payload of \mbox{\hyperlink{structmrq__thermal__bpmp__to__host__request}{mrq\+\_\+thermal\+\_\+bpmp\+\_\+to\+\_\+host\+\_\+request}}.
