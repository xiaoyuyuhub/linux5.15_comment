{\footnotesize\ttfamily \mbox{\hyperlink{include_2linux_2types_8h_afaa87723b8417d40fcf45b7330261ef9}{bool}} \mbox{\hyperlink{compiler__attributes_8h_ab8d4aa7e9ca368db7220dc9747189f1c}{\+\_\+\+\_\+pure}} glob\+\_\+match (\begin{DoxyParamCaption}\item[{char const $\ast$}]{pat,  }\item[{char const $\ast$}]{str }\end{DoxyParamCaption})}

glob\+\_\+match -\/ Shell-\/style pattern matching, like !fnmatch(pat, str, 0) @pat\+: Shell-\/style pattern to match, e.\+g. \char`\"{}$\ast$.\mbox{[}ch\mbox{]}\char`\"{}. @str\+: String to match. \mbox{\hyperlink{classThe}{The}} pattern must match the entire string.

Perform shell-\/style glob matching, returning true (1) if the match succeeds, or false (0) if it fails. Equivalent to !fnmatch(@pat, @str, 0).

Pattern metacharacters are ?, $\ast$, \mbox{[} and . (And, inside character classes, !, -\/ and \mbox{]}.)

This is small and simple implementation intended for device blacklists where a string is matched against a number of patterns. Thus, it does not preprocess the patterns. It is non-\/recursive, and run-\/time is at most quadratic\+: strlen(@str)$\ast$strlen(@pat).

An example of the worst case is glob\+\_\+match(\char`\"{}$\ast$aaaaa\char`\"{}, \char`\"{}aaaaaaaaaa\char`\"{}); it takes 6 passes over the pattern before matching the string.

Like !fnmatch(@pat, @str, 0) and unlike the shell, this does N\+OT treat / or leading . specially; it isn\textquotesingle{}t actually used for pathnames.

Note that according to glob(7) (and unlike bash), character classes are complemented by a leading !; this does not support the regex-\/style \mbox{[}$^\wedge$a-\/z\mbox{]} syntax.
