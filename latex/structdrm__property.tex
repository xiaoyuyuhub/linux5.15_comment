\doxysubsection{Detailed Description}
struct \mbox{\hyperlink{structdrm__property}{drm\+\_\+property}} -\/ modeset object property

This structure represent a modeset object property. It combines both the name of the property with the set of permissible values. This means that when a driver wants to use a property with the same name on different objects, but with different value ranges, then it must create property for each one. An example would be rotation of \&\mbox{\hyperlink{structdrm__plane}{drm\+\_\+plane}}, when e.\+g. the primary plane cannot be rotated. But if both the name and the value range match, then the same property structure can be instantiated multiple times for the same object. Userspace must be able to cope with this and cannot assume that the same symbolic property will have the same modeset object ID on all modeset objects.

Properties are created by one of the special functions, as explained in detail in the @flags structure member.

To actually expose a property it must be attached to each object using \mbox{\hyperlink{drm__mode__object_8h_ad12438a835ffb8f0a5aa20d393595a9f}{drm\+\_\+object\+\_\+attach\+\_\+property()}}. Currently properties can only be attached to \&\mbox{\hyperlink{structdrm__connector}{drm\+\_\+connector}}, \&\mbox{\hyperlink{structdrm__crtc}{drm\+\_\+crtc}} and \&\mbox{\hyperlink{structdrm__plane}{drm\+\_\+plane}}.

Properties are also used as the generic metadatatransport for the atomic I\+O\+C\+TL. Everything that was set directly in structures in the legacy modeset I\+O\+C\+T\+Ls (like the plane source or destination windows, or e.\+g. the links to the C\+R\+TC) is exposed as a property with the D\+R\+M\+\_\+\+M\+O\+D\+E\+\_\+\+P\+R\+O\+P\+\_\+\+A\+T\+O\+M\+IC flag set.

@flags\+:

Property flags and type. A property needs to be one of the following types\+:

D\+R\+M\+\_\+\+M\+O\+D\+E\+\_\+\+P\+R\+O\+P\+\_\+\+R\+A\+N\+GE Range properties report their minimum and maximum admissible unsigned values. \mbox{\hyperlink{classThe}{The}} K\+MS core verifies that values set by application fit in that range. \mbox{\hyperlink{classThe}{The}} range is unsigned. Range properties are created using \mbox{\hyperlink{drm__property_8h_a4d7cb4a5fce2c1bb37e7b294cfb04d9f}{drm\+\_\+property\+\_\+create\+\_\+range()}}.

D\+R\+M\+\_\+\+M\+O\+D\+E\+\_\+\+P\+R\+O\+P\+\_\+\+S\+I\+G\+N\+E\+D\+\_\+\+R\+A\+N\+GE Range properties report their minimum and maximum admissible unsigned values. \mbox{\hyperlink{classThe}{The}} K\+MS core verifies that values set by application fit in that range. \mbox{\hyperlink{classThe}{The}} range is signed. Range properties are created using \mbox{\hyperlink{drm__property_8h_a1aa894f905649985630814a6d9891682}{drm\+\_\+property\+\_\+create\+\_\+signed\+\_\+range()}}.

D\+R\+M\+\_\+\+M\+O\+D\+E\+\_\+\+P\+R\+O\+P\+\_\+\+E\+N\+UM Enumerated properties take a numerical value that ranges from 0 to the number of enumerated values defined by the property minus one, and associate a free-\/formed string name to each value. Applications can retrieve the list of defined value-\/name pairs and use the numerical value to get and set property instance values. Enum properties are created using \mbox{\hyperlink{drm__property_8h_a0346d415aa9940c648acfe537bf6cee5}{drm\+\_\+property\+\_\+create\+\_\+enum()}}.

D\+R\+M\+\_\+\+M\+O\+D\+E\+\_\+\+P\+R\+O\+P\+\_\+\+B\+I\+T\+M\+A\+SK Bitmask properties are enumeration properties that additionally restrict all enumerated values to the 0..63 range. Bitmask property instance values combine one or more of the enumerated bits defined by the property. Bitmask properties are created using \mbox{\hyperlink{drm__property_8h_ac227ffbf6714c7fd6be9978431abe194}{drm\+\_\+property\+\_\+create\+\_\+bitmask()}}.

D\+R\+M\+\_\+\+M\+O\+D\+E\+\_\+\+P\+R\+O\+P\+\_\+\+O\+B\+J\+E\+CT Object properties are used to link modeset objects. This is used extensively in the atomic support to create the display pipeline, by linking \&\mbox{\hyperlink{structdrm__framebuffer}{drm\+\_\+framebuffer}} to \&\mbox{\hyperlink{structdrm__plane}{drm\+\_\+plane}}, \&\mbox{\hyperlink{structdrm__plane}{drm\+\_\+plane}} to \&\mbox{\hyperlink{structdrm__crtc}{drm\+\_\+crtc}} and \&\mbox{\hyperlink{structdrm__connector}{drm\+\_\+connector}} to \&\mbox{\hyperlink{structdrm__crtc}{drm\+\_\+crtc}}. An object property can only link to a specific type of \&\mbox{\hyperlink{structdrm__mode__object}{drm\+\_\+mode\+\_\+object}}, this limit is enforced by the core. Object properties are created using \mbox{\hyperlink{drm__property_8h_a116a73895d199c1a12b468ac468dc2de}{drm\+\_\+property\+\_\+create\+\_\+object()}}.

Object properties work like blob properties, but in a more general fashion. They are limited to atomic drivers and must have the D\+R\+M\+\_\+\+M\+O\+D\+E\+\_\+\+P\+R\+O\+P\+\_\+\+A\+T\+O\+M\+IC flag set.

D\+R\+M\+\_\+\+M\+O\+D\+E\+\_\+\+P\+R\+O\+P\+\_\+\+B\+L\+OB Blob properties store a binary blob without any format restriction. \mbox{\hyperlink{classThe}{The}} binary blobs are created as K\+MS standalone objects, and blob property instance values store the ID of their associated blob object. Blob properties are created by calling \mbox{\hyperlink{drm__property_8h_ac0e4031c280ab74fe1866e86f29decad}{drm\+\_\+property\+\_\+create()}} with D\+R\+M\+\_\+\+M\+O\+D\+E\+\_\+\+P\+R\+O\+P\+\_\+\+B\+L\+OB as the type.

Actual blob objects to contain blob data are created using \mbox{\hyperlink{drm__property_8h_ad34c6976a6ba6db01f2801259a75449f}{drm\+\_\+property\+\_\+create\+\_\+blob()}}, or through the corresponding I\+O\+C\+TL.

Besides the built-\/in limit to only accept blob objects blob properties work exactly like object properties. \mbox{\hyperlink{classThe}{The}} only reasons blob properties exist is backwards compatibility with existing userspace.

In addition a property can have any combination of the below flags\+:

D\+R\+M\+\_\+\+M\+O\+D\+E\+\_\+\+P\+R\+O\+P\+\_\+\+A\+T\+O\+M\+IC Set for properties which encode atomic modeset state. Such properties are not exposed to legacy userspace.

D\+R\+M\+\_\+\+M\+O\+D\+E\+\_\+\+P\+R\+O\+P\+\_\+\+I\+M\+M\+U\+T\+A\+B\+LE Set for properties whose values cannot be changed by userspace. \mbox{\hyperlink{classThe}{The}} kernel is allowed to update the value of these properties. This is generally used to expose probe state to userspace, e.\+g. the E\+D\+ID, or the connector path property on DP M\+ST sinks. Kernel can update the value of an immutable property by calling \mbox{\hyperlink{drm__mode__object_8h_a13c1c186f6bacada4fc341fece9e9b52}{drm\+\_\+object\+\_\+property\+\_\+set\+\_\+value()}}. \mbox{\Hypertarget{structdrm__property_a8a2e46f2e5656d3858a0c8c4163b141f}\label{structdrm__property_a8a2e46f2e5656d3858a0c8c4163b141f}}
