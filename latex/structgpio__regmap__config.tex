\doxysubsection{Detailed Description}
struct \mbox{\hyperlink{structgpio__regmap__config}{gpio\+\_\+regmap\+\_\+config}} -\/ Description of a generic regmap \mbox{\hyperlink{structgpio__chip}{gpio\+\_\+chip}}. @parent\+: \mbox{\hyperlink{classThe}{The}} parent device @regmap\+: \mbox{\hyperlink{classThe}{The}} regmap used to access the registers given, the name of the device is used @fwnode\+: (Optional) \mbox{\hyperlink{classThe}{The}} firmware node. If not given, the fwnode of the parent is used. @label\+: (Optional) Descriptive name for G\+P\+IO controller. If not given, the name of the device is used. @ngpio\+: Number of G\+P\+I\+Os @names\+: (Optional) Array of names for gpios @reg\+\_\+dat\+\_\+base\+: (Optional) (in) register base address @reg\+\_\+set\+\_\+base\+: (Optional) set register base address @reg\+\_\+clr\+\_\+base\+: (Optional) clear register base address @reg\+\_\+dir\+\_\+in\+\_\+base\+: (Optional) in setting register base address @reg\+\_\+dir\+\_\+out\+\_\+base\+: (Optional) out setting register base address @reg\+\_\+stride\+: (Optional) May be set if the registers (of the same type, dat, set, etc) are not consecutive. @ngpio\+\_\+per\+\_\+reg\+: Number of G\+P\+I\+Os per register @irq\+\_\+domain\+: (Optional) I\+RQ domain if the controller is interrupt-\/capable @reg\+\_\+mask\+\_\+xlate\+: (Optional) Translates base address and G\+P\+IO offset to a register/bitmask pair. If not given the default gpio\+\_\+regmap\+\_\+simple\+\_\+xlate() is used. @drvdata\+: (Optional) Pointer to driver specific data which is not used by gpio-\/remap but is provided \char`\"{}as is\char`\"{} to the driver callback(s).

\mbox{\hyperlink{classThe}{The}} -\/$>$reg\+\_\+mask\+\_\+xlate translates a given base address and G\+P\+IO offset to register and mask pair. \mbox{\hyperlink{classThe}{The}} base address is one of the given register base addresses in this structure.

Although all register base addresses are marked as optional, there are several rules\+:
\begin{DoxyEnumerate}
\item if you only have @reg\+\_\+dat\+\_\+base set, then it is input-\/only
\item if you only have @reg\+\_\+set\+\_\+base set, then it is output-\/only
\item if you have either @reg\+\_\+dir\+\_\+in\+\_\+base or @reg\+\_\+dir\+\_\+out\+\_\+base set, then you have to set both @reg\+\_\+dat\+\_\+base and @reg\+\_\+set\+\_\+base
\item if you have @reg\+\_\+set\+\_\+base set, you may also set @reg\+\_\+clr\+\_\+base to have two different registers for setting and clearing the output. This is also valid for the output-\/only case.
\item @reg\+\_\+dir\+\_\+in\+\_\+base and @reg\+\_\+dir\+\_\+out\+\_\+base are exclusive; is there really hardware which has redundant registers?
\end{DoxyEnumerate}

Note\+: All base addresses may have the special value G\+P\+I\+O\+\_\+\+R\+E\+G\+M\+A\+P\+\_\+\+A\+D\+D\+R\+\_\+\+Z\+E\+RO which forces the address to the value 0.
