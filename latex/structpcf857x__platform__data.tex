\doxysubsection{Detailed Description}
struct \mbox{\hyperlink{structpcf857x__platform__data}{pcf857x\+\_\+platform\+\_\+data}} -\/ data to set up pcf857x driver @gpio\+\_\+base\+: number of the chip\textquotesingle{}s first G\+P\+IO @n\+\_\+latch\+: optional bit-\/inverse of initial register value; if you leave this initialized to zero the driver will act like the chip was just reset @setup\+: optional callback issued once the G\+P\+I\+Os are valid @teardown\+: optional callback issued before the G\+P\+I\+Os are invalidated @context\+: optional parameter passed to \mbox{\hyperlink{structpcf857x__platform__data_a2c45a575e374ac3b3283e9459e03a0fe}{setup()}} and \mbox{\hyperlink{structpcf857x__platform__data_a57810b4a842057c71ae9c3a7a11dff76}{teardown()}}

In addition to the \mbox{\hyperlink{linux_2i2c_8h_a38b69b134457052d7ebbd31ddae7cdb6}{I2\+C\+\_\+\+B\+O\+A\+R\+D\+\_\+\+I\+N\+F\+O()}} state appropriate to each chip, the \mbox{\hyperlink{structi2c__board__info}{i2c\+\_\+board\+\_\+info}} used with the pcf875x driver must provide its platform\+\_\+data (pointer to one of these structures) with at least the gpio\+\_\+base value initialized.

\mbox{\hyperlink{classThe}{The}} @setup callback may be used with the kind of board-\/specific glue which hands the (now-\/valid) G\+P\+I\+Os to other drivers, or which puts devices in their initial states using these G\+P\+I\+Os.

These G\+P\+IO chips are only \char`\"{}quasi-\/bidirectional\char`\"{}; read the chip specs to understand the behavior. They don\textquotesingle{}t have separate registers to record which pins are used for input or output, record which output values are driven, or provide access to input values. That must be inferred by reading the chip\textquotesingle{}s value and knowing the last value written to it. If you leave n\+\_\+latch initialized to zero, that last written value is presumed to be all ones (as if the chip were just reset).
