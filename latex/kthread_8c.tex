C\+PU hotplug\+: \mbox{\hyperlink{classThe}{The}} kthread worker A\+PI is simple and generic. It just provides a way to create, use, and destroy workers.

It is up to the A\+PI user how to handle C\+PU hotplug. They have to decide how to handle pending work items, prevent queuing new ones, and restore the functionality when the C\+PU goes off and on. There are a few catches\+:


\begin{DoxyItemize}
\item C\+PU affinity gets lost when it is scheduled on an offline C\+PU.
\item \mbox{\hyperlink{classThe}{The}} worker might not exist when the C\+PU was off when the user created the workers.
\end{DoxyItemize}

Good practice is to implement two C\+PU hotplug callbacks and to destroy/create the worker when the C\+PU goes down/up.
