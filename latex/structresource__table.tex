\doxysubsection{Detailed Description}
struct \mbox{\hyperlink{structresource__table}{resource\+\_\+table}} -\/ firmware resource table header @ver\+: version number @num\+: number of resource entries @reserved\+: reserved (must be zero) @offset\+: array of offsets pointing at the various resource entries

A resource table is essentially a list of system resources required by the remote processor. It may also include configuration entries. If needed, the remote processor firmware should contain this table as a dedicated \char`\"{}.\+resource\+\_\+table\char`\"{} E\+LF section.

Some resources entries are mere announcements, where the host is informed of specific remoteproc configuration. Other entries require the host to do something (e.\+g. allocate a system resource). Sometimes a negotiation is expected, where the firmware requests a resource, and once allocated, the host should provide back its details (e.\+g. address of an allocated memory region).

\mbox{\hyperlink{classThe}{The}} header of the resource table, as expressed by this structure, \mbox{\hyperlink{protocolcontains-p}{contains}} a version number (should we need to change this format in the future), the number of available resource entries, and their offsets in the table.

Immediately following this header are the resource entries themselves, each of which begins with a resource entry header (as described below).
