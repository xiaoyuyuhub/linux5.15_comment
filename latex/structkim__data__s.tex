\doxysubsection{Detailed Description}
struct \mbox{\hyperlink{structkim__data__s}{kim\+\_\+data\+\_\+s}} -\/ the K\+IM internal data, embedded as the platform\textquotesingle{}s drv data. One for each ST device in the system. @uim\+\_\+pid\+: K\+IM needs to communicate with U\+IM to request to install the ldisc by opening U\+A\+RT when \mbox{\hyperlink{protocolprotocol-p}{protocol}} drivers register. @kim\+\_\+pdev\+: the platform device added in one of the board-\/\+X\+X.\+c file in arch/\+X\+X/ directory, 1 for each ST device. @kim\+\_\+rcvd\+: completion handler to notify when data was received, mainly used during fw download, which involves multiple send/wait for each of the H\+C\+I-\/\+VS commands. @ldisc\+\_\+installed\+: completion handler to notify that the U\+IM accepted the request to install ldisc, notify from tty\+\_\+open which suggests the ldisc was properly installed. @resp\+\_\+buffer\+: data buffer for the .bts fw file name. @fw\+\_\+entry\+: firmware class struct to request/release the fw. @rx\+\_\+state\+: the rx state for kim\textquotesingle{}s receive func during fw download. @rx\+\_\+count\+: the rx count for the kim\textquotesingle{}s receive func during fw download. @rx\+\_\+skb\+: all of fw data might not come at once, and hence data storage for whole of the fw response, only H\+C\+I\+\_\+\+E\+V\+E\+N\+Ts and hence diff from ST\textquotesingle{}s response. @core\+\_\+data\+: ST core\textquotesingle{}s data, which mainly is the tty\textquotesingle{}s disc\+\_\+data \begin{DoxyVersion}{Version}
\+: chip version available via a sysfs entry.
