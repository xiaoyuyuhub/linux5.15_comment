enum drm\+\_\+plane\+\_\+type -\/ uapi plane type enumeration

For historical reasons not all planes are made the same. This enumeration is used to tell the different types of planes apart to implement the different uapi semantics for them. For userspace which is universal plane aware and which is using that atomic I\+O\+C\+TL there\textquotesingle{}s no difference between these planes (beyong what the driver and hardware can support of course).

For compatibility with legacy userspace, only overlay planes are made available to userspace by default. Userspace clients may set the \&D\+R\+M\+\_\+\+C\+L\+I\+E\+N\+T\+\_\+\+C\+A\+P\+\_\+\+U\+N\+I\+V\+E\+R\+S\+A\+L\+\_\+\+P\+L\+A\+N\+ES client capability bit to indicate that they wish to receive a universal plane list containing all plane types. See also \mbox{\hyperlink{drm__plane_8h_a92faf0e2ef05aafdc5647b2887185e50}{drm\+\_\+for\+\_\+each\+\_\+legacy\+\_\+plane()}}.

In addition to setting each plane\textquotesingle{}s type, drivers need to setup the \&\mbox{\hyperlink{structdrm__crtc_a35e663877e85906f5c82f8361b5f06d9}{drm\+\_\+crtc.\+primary}} and optionally \&\mbox{\hyperlink{structdrm__crtc_ad117b69fbb18167ae47aec856169f133}{drm\+\_\+crtc.\+cursor}} pointers for legacy I\+O\+C\+T\+Ls. See drm\+\_\+crtc\+\_\+init\+\_\+with\+\_\+planes().
