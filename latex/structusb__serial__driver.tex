\doxysubsection{Detailed Description}
\mbox{\hyperlink{structusb__serial__driver}{usb\+\_\+serial\+\_\+driver}} -\/ describes a usb serial driver @description\+: pointer to a string that describes this driver. This string used in the syslog messages when a device is inserted or removed. @id\+\_\+table\+: pointer to a list of \mbox{\hyperlink{structusb__device__id}{usb\+\_\+device\+\_\+id}} structures that define all of the devices this structure can support. @num\+\_\+ports\+: the number of different ports this device will have. @num\+\_\+bulk\+\_\+in\+: minimum number of bulk-\/in endpoints @num\+\_\+bulk\+\_\+out\+: minimum number of bulk-\/out endpoints @num\+\_\+interrupt\+\_\+in\+: minimum number of interrupt-\/in endpoints @num\+\_\+interrupt\+\_\+out\+: minimum number of interrupt-\/out endpoints @bulk\+\_\+in\+\_\+size\+: minimum number of bytes to allocate for bulk-\/in buffer (0 = end-\/point size) @bulk\+\_\+out\+\_\+size\+: bytes to allocate for bulk-\/out buffer (0 = end-\/point size) @calc\+\_\+num\+\_\+ports\+: pointer to a function to determine how many ports this device has dynamically. It can also be used to verify the number of endpoints or to modify the port-\/endpoint mapping. It will be called after the \mbox{\hyperlink{structusb__serial__driver_a3b8f83125de29a9290f65b119f50f13b}{probe()}} callback is called, but before \mbox{\hyperlink{structusb__serial__driver_a6e12e5eabc3b306f1819d6c0d157251c}{attach()}}. @probe\+: pointer to the driver\textquotesingle{}s probe function. This will be called when the device is inserted into the system, but before the device has been fully initialized by the \mbox{\hyperlink{structusb__serial}{usb\+\_\+serial}} subsystem. Use this function to download any firmware to the device, or any other early initialization that might be needed. Return 0 to continue on with the initialization sequence. Anything else will abort it. @attach\+: pointer to the driver\textquotesingle{}s attach function. This will be called when the struct \mbox{\hyperlink{structusb__serial}{usb\+\_\+serial}} structure is fully set up. Do any local initialization of the device, or any private memory structure allocation at this point in time. @disconnect\+: pointer to the driver\textquotesingle{}s disconnect function. This will be called when the device is unplugged or unbound from the driver. @release\+: pointer to the driver\textquotesingle{}s release function. This will be called when the \mbox{\hyperlink{structusb__serial}{usb\+\_\+serial}} data structure is about to be destroyed. @usb\+\_\+driver\+: pointer to the struct usb\+\_\+driver that controls this device. This is necessary to allow dynamic ids to be added to the driver from sysfs.

This structure is defines a U\+SB Serial driver. It provides all of the information that the U\+SB serial core code needs. If the function pointers are defined, then the U\+SB serial core code will call them when the corresponding tty port functions are called. If they are not called, the generic serial function will be used instead.

\mbox{\hyperlink{classThe}{The}} driver.\+owner field should be set to the module owner of this driver. \mbox{\hyperlink{classThe}{The}} driver.\+name field should be set to the name of this driver (remember it will show up in sysfs, so it needs to be short and to the point. Using the module name is a good idea.)
