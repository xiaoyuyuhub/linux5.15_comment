@possible\+\_\+clones\+: Bitmask of potential sibling encoders for cloning, using \mbox{\hyperlink{drm__encoder_8h_ac2f38fcedd0eb3b6985bb4de83343fd4}{drm\+\_\+encoder\+\_\+index()}} as the index into the bitfield. \mbox{\hyperlink{classThe}{The}} driver must set the bits for all \&\mbox{\hyperlink{structdrm__encoder}{drm\+\_\+encoder}} objects which can clone a \&\mbox{\hyperlink{structdrm__crtc}{drm\+\_\+crtc}} together with this encoder before calling \mbox{\hyperlink{drm__drv_8h_aa400aa845e16d611d6db9ee0e7e6726e}{drm\+\_\+dev\+\_\+register()}}. Drivers should set the bit representing the encoder itself, too. Cloning bits should be set such that when two encoders can be used in a cloned configuration, they both should have each another bits set.

As an exception to the above rule if the driver doesn\textquotesingle{}t implement any cloning it can leave @possible\+\_\+clones set to 0. \mbox{\hyperlink{classThe}{The}} core will automagically fix this up by setting the bit for the encoder itself.

You will get a W\+A\+RN if you get this wrong in the driver.

Note that since encoder objects can\textquotesingle{}t be hotplugged the assigned indices are stable and hence known before registering all objects. \mbox{\Hypertarget{structdrm__encoder_ab6d771a3a146997aa3515e02aedf66e7}\label{structdrm__encoder_ab6d771a3a146997aa3515e02aedf66e7}}
