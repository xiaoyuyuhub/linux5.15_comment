Memory type region registers control the caching on newer Intel and non Intel processors. This function allows drivers to request an M\+T\+RR is added. \mbox{\hyperlink{classThe}{The}} details and hardware specifics of each processor\textquotesingle{}s implementation are hidden from the caller, but nevertheless the caller should expect to need to provide a power of two size on an equivalent power of two boundary.

set\+\_\+mtrr -\/ update mtrrs on all processors @reg\+: mtrr in question @base\+: mtrr base @size\+: mtrr size @type\+: mtrr type

This is kinda tricky, but fortunately, Intel spelled it out for us cleanly\+:


\begin{DoxyEnumerate}
\item Queue work to do the following on all processors\+:
\item Disable Interrupts
\item Wait for all procs to do so
\item Enter no-\/fill cache mode
\item Flush caches
\item Clear P\+GE bit
\item Flush all T\+L\+Bs
\item Disable all range registers
\item Update the M\+T\+R\+Rs
\item Enable all range registers
\item Flush all T\+L\+Bs and caches again
\item Enter normal cache mode and reenable caching
\item Set P\+GE
\item Wait for buddies to catch up
\item Enable interrupts.
\end{DoxyEnumerate}

\mbox{\hyperlink{classWhat}{What}} does that mean for us? Well, \mbox{\hyperlink{stop__machine_8c_accd2ff0c7479d51505cabf6f8bc5e973}{stop\+\_\+machine()}} will ensure that the rendezvous handler is started on each C\+PU. And in lockstep they do the state transition of disabling interrupts, updating M\+T\+RR\textquotesingle{}s (the C\+PU vendors may each do it differently, so we call mtrr\+\_\+if-\/$>$\mbox{\hyperlink{nl80211_8h_aa32dc92d0a8e963b0834f4f6a0f97b18}{set()}} callback and let them take care of it.) and enabling interrupts.
