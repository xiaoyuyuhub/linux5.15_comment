D\+OC\+: memblock overview

Memblock is a method of managing memory regions during the early boot period when the usual kernel memory allocators are not up and running.

Memblock views the system memory as collections of contiguous regions. There are several types of these collections\+:


\begin{DoxyItemize}
\item {\ttfamily memory} -\/ describes the physical memory available to the kernel; this may differ from the actual physical memory installed in the system, for instance when the memory is restricted with {\ttfamily mem=} command line parameter
\item {\ttfamily reserved} -\/ describes the regions that were allocated
\item {\ttfamily physmem} -\/ describes the actual physical memory available during boot regardless of the possible restrictions and memory hot(un)plug; the {\ttfamily physmem} type is only available on some architectures.
\end{DoxyItemize}

Each region is represented by struct memblock\+\_\+region that defines the region extents, its attributes and N\+U\+MA node id on N\+U\+MA systems. Every memory type is described by the struct memblock\+\_\+type which \mbox{\hyperlink{protocolcontains-p}{contains}} an array of memory regions along with the allocator metadata. \mbox{\hyperlink{classThe}{The}} \char`\"{}memory\char`\"{} and \char`\"{}reserved\char`\"{} types are nicely wrapped with struct memblock. This structure is statically initialized at build time. \mbox{\hyperlink{classThe}{The}} region arrays are initially sized to I\+N\+I\+T\+\_\+\+M\+E\+M\+B\+L\+O\+C\+K\+\_\+\+R\+E\+G\+I\+O\+NS for \char`\"{}memory\char`\"{} and I\+N\+I\+T\+\_\+\+M\+E\+M\+B\+L\+O\+C\+K\+\_\+\+R\+E\+S\+E\+R\+V\+E\+D\+\_\+\+R\+E\+G\+I\+O\+NS for \char`\"{}reserved\char`\"{}. \mbox{\hyperlink{classThe}{The}} region array for \char`\"{}physmem\char`\"{} is initially sized to I\+N\+I\+T\+\_\+\+P\+H\+Y\+S\+M\+E\+M\+\_\+\+R\+E\+G\+I\+O\+NS. \mbox{\hyperlink{classThe}{The}} \mbox{\hyperlink{memblock_8c_a2f7c4876018ab925b1509288006e2a50}{memblock\+\_\+allow\+\_\+resize()}} enables automatic resizing of the region arrays during addition of new regions. This feature should be used with care so that memory allocated for the region array will not overlap with areas that should be reserved, for example initrd.

\mbox{\hyperlink{classThe}{The}} early architecture setup should tell memblock what the physical memory layout is by using \mbox{\hyperlink{memblock_8c_aa1c37d02973fd2f0eaf4f976ebe90ac5}{memblock\+\_\+add()}} or \mbox{\hyperlink{memblock_8c_ab067fae74724fc17bca83b308b068a75}{memblock\+\_\+add\+\_\+node()}} functions. \mbox{\hyperlink{classThe}{The}} first function does not assign the region to a N\+U\+MA node and it is appropriate for U\+MA systems. Yet, it is possible to use it on N\+U\+MA systems as well and assign the region to a N\+U\+MA node later in the setup process using \mbox{\hyperlink{memblock_8c_ad0e685a82a3772b25b78e30e34fa8595}{memblock\+\_\+set\+\_\+node()}}. \mbox{\hyperlink{classThe}{The}} \mbox{\hyperlink{memblock_8c_ab067fae74724fc17bca83b308b068a75}{memblock\+\_\+add\+\_\+node()}} performs such an assignment directly.

Once memblock is setup the memory can be allocated using one of the A\+PI variants\+:


\begin{DoxyItemize}
\item memblock\+\_\+phys\+\_\+alloc$\ast$() -\/ these functions return the {\bfseries{physical}} address of the allocated memory
\item memblock\+\_\+alloc$\ast$() -\/ these functions return the {\bfseries{virtual}} address of the allocated memory.
\end{DoxyItemize}

Note, that both A\+PI variants use implicit assumptions about allowed memory ranges and the fallback methods. Consult the documentation of \mbox{\hyperlink{memblock_8c_ab6f5f89331578939f4812549b1bf5ddc}{memblock\+\_\+alloc\+\_\+internal()}} and \mbox{\hyperlink{memblock_8c_a23875c89e572709cf1ad3fe305b8dc52}{memblock\+\_\+alloc\+\_\+range\+\_\+nid()}} functions for more elaborate description.

As the system boot progresses, the architecture specific \mbox{\hyperlink{init__32_8c_a3d0bcff34481767e7389c17dd0a23783}{mem\+\_\+init()}} function frees all the memory to the buddy page allocator.

Unless an architecture enables C\+O\+N\+F\+I\+G\+\_\+\+A\+R\+C\+H\+\_\+\+K\+E\+E\+P\+\_\+\+M\+E\+M\+B\+L\+O\+CK, the memblock data structures (except \char`\"{}physmem\char`\"{}) will be discarded after the system initialization completes. \mbox{\Hypertarget{memblock_8c_ae12472a5d712c8ded1d522488983049a}\label{memblock_8c_ae12472a5d712c8ded1d522488983049a}}
