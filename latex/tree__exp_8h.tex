synchronize\+\_\+rcu\+\_\+expedited -\/ Brute-\/force R\+CU grace period

Wait for an R\+CU grace period, but expedite it. \mbox{\hyperlink{classThe}{The}} basic idea is to I\+PI all non-\/idle non-\/nohz online C\+P\+Us. \mbox{\hyperlink{classThe}{The}} I\+PI handler checks whether the C\+PU is in an R\+CU critical section, and if so, it sets a flag that causes the outermost \mbox{\hyperlink{rcupdate_8h_a07db93454b6994cf0af302584e84ffb9}{rcu\+\_\+read\+\_\+unlock()}} to report the quiescent state for R\+C\+U-\/preempt or asks the scheduler for help for R\+C\+U-\/sched. On the other hand, if the C\+PU is not in an R\+CU read-\/side critical section, the I\+PI handler reports the quiescent state immediately.

Although this is a great improvement over previous expedited implementations, it is still unfriendly to real-\/time workloads, so is thus not recommended for any sort of common-\/case code. In fact, if you are using \mbox{\hyperlink{tree__exp_8h_a083fbbb282ef5a0d32d2f99d74372dc8}{synchronize\+\_\+rcu\+\_\+expedited()}} in a loop, please restructure your code to batch your updates, and then use a single \mbox{\hyperlink{tiny_8c_a2a82b0ecedfdd3957789e90bdfd47756}{synchronize\+\_\+rcu()}} instead.
