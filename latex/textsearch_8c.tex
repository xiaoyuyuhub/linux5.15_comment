D\+OC\+: ts\+\_\+intro I\+N\+T\+R\+O\+D\+U\+C\+T\+I\+ON

\mbox{\hyperlink{classThe}{The}} textsearch infrastructure provides text searching facilities for both linear and non-\/linear data. Individual search algorithms are implemented in modules and chosen by the user.

A\+R\+C\+H\+I\+T\+E\+C\+T\+U\+RE

(1) User configures a search by calling \mbox{\hyperlink{textsearch_8c_adc9e94c1300658abf5a9acfd42237c8b}{textsearch\+\_\+prepare()}} specifying the search parameters such as the pattern and algorithm name. (2) Core requests the algorithm to allocate and initialize a search configuration according to the specified parameters. (3) User starts the search(es) by calling \mbox{\hyperlink{textsearch_8h_af7da678fe3488622c895088b8687d459}{textsearch\+\_\+find()}} or \mbox{\hyperlink{textsearch_8h_ae544702f18feffd8cd951cd96c478c82}{textsearch\+\_\+next()}} to fetch subsequent occurrences. A state variable is provided to the algorithm to store persistent variables. (4) Core eventually resets the search offset and forwards the find() request to the algorithm. (5) Algorithm calls \mbox{\hyperlink{decompress__bunzip2_8c_a50f73fbeb97683b408681991e6e16e5d}{get\+\_\+next\+\_\+block()}} provided by the user continuously to fetch the data to be searched in block by block. (6) Algorithm invokes \mbox{\hyperlink{bpf__preload__kern_8c_a20420413438ce7e9cb7b3dea92d7478d}{finish()}} after the last call to get\+\_\+next\+\_\+block to clean up any leftovers from get\+\_\+next\+\_\+block. (Optional) (7) User destroys the configuration by calling \mbox{\hyperlink{textsearch_8c_a6bccf86509d917875a6535b0651d011a}{textsearch\+\_\+destroy()}}. (8) Core notifies the algorithm to destroy algorithm specific allocations. (Optional)

U\+S\+A\+GE

Before a search can be performed, a configuration must be created by calling \mbox{\hyperlink{textsearch_8c_adc9e94c1300658abf5a9acfd42237c8b}{textsearch\+\_\+prepare()}} specifying the searching algorithm, the pattern to look for and flags. As a flag, you can set T\+S\+\_\+\+I\+G\+N\+O\+R\+E\+C\+A\+SE to perform case insensitive matching. But it might slow down performance of algorithm, so you should use it at own your risk. \mbox{\hyperlink{classThe}{The}} returned configuration may then be used for an arbitrary amount of times and even in parallel as long as a separate struct \mbox{\hyperlink{structts__state}{ts\+\_\+state}} variable is provided to every instance.

\mbox{\hyperlink{classThe}{The}} actual search is performed by either calling \mbox{\hyperlink{textsearch_8c_a5b54b22a96edb9e72a5a263d8b39f1b6}{textsearch\+\_\+find\+\_\+continuous()}} for linear data or by providing an own \mbox{\hyperlink{decompress__bunzip2_8c_a50f73fbeb97683b408681991e6e16e5d}{get\+\_\+next\+\_\+block()}} implementation and calling \mbox{\hyperlink{textsearch_8h_af7da678fe3488622c895088b8687d459}{textsearch\+\_\+find()}}. Both functions return the position of the first occurrence of the pattern or U\+I\+N\+T\+\_\+\+M\+AX if no match was found. Subsequent occurrences can be found by calling \mbox{\hyperlink{textsearch_8h_ae544702f18feffd8cd951cd96c478c82}{textsearch\+\_\+next()}} regardless of the linearity of the data.

Once you\textquotesingle{}re done using a configuration it must be given back via textsearch\+\_\+destroy.
