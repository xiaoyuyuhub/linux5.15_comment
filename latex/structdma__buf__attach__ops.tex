@move\+\_\+notify\+: \mbox{[}optional\mbox{]} notification that the D\+M\+A-\/buf is moving

If this callback is provided the framework can avoid pinning the backing store while mappings exists.

This callback is called with the lock of the reservation object associated with the \mbox{\hyperlink{structdma__buf}{dma\+\_\+buf}} held and the mapping function must be called with this lock held as well. This makes sure that no mapping is created concurrently with an ongoing move operation.

Mappings stay valid and are not directly affected by this callback. But the D\+M\+A-\/buf can now be in a different physical location, so all mappings should be destroyed and re-\/created as soon as possible.

New mappings can be created after this callback returns, and will point to the new location of the D\+M\+A-\/buf.
