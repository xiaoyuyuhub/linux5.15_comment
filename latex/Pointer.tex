\mbox{\hyperlink{contiguous_8c_ac95049c6919685e53f70b3edc7b4a20b}{dma\+\_\+free\+\_\+contiguous()}} -\/ release allocated pages @dev\+: Pointer to device for which the pages were allocated.

@size\+: Size of allocated pages.

This function releases memory allocated by \mbox{\hyperlink{contiguous_8c_a92751a27a1a3e17c3dff09bb11a943c3}{dma\+\_\+alloc\+\_\+contiguous()}}. As the cma\+\_\+release returns false when provided pages do not belong to contiguous area and true otherwise, this function then does a fallback \mbox{\hyperlink{page__alloc_8c_a09a84df4c6cb817075a2eece7c7c0345}{\+\_\+\+\_\+free\+\_\+pages()}} upon a false-\/return.

kmap -\/ Map a page for long term usage

Returns\+: \mbox{\hyperlink{classThe}{The}} virtual address of the mapping

Can only be invoked from preemptible task context because on 32bit systems with C\+O\+N\+F\+I\+G\+\_\+\+H\+I\+G\+H\+M\+EM enabled this function might sleep.

For systems with C\+O\+N\+F\+I\+G\+\_\+\+H\+I\+G\+H\+M\+EM=n and for pages in the low memory area this returns the virtual address of the direct kernel mapping.

\mbox{\hyperlink{classThe}{The}} returned virtual address is globally visible and valid up to the point where it is unmapped via \mbox{\hyperlink{include_2linux_2highmem_8h_a8c784a6f8e3f1de05d625a30d0fdfda1}{kunmap()}}. \mbox{\hyperlink{classThe}{The}} pointer can be handed to other contexts.

For highmem pages on 32bit systems this can be slow as the mapping space is limited and protected by a global lock. In case that there is no mapping slot available the function blocks until a slot is released via \mbox{\hyperlink{include_2linux_2highmem_8h_a8c784a6f8e3f1de05d625a30d0fdfda1}{kunmap()}}.

kmap\+\_\+local\+\_\+page -\/ Map a page for temporary usage

Returns\+: \mbox{\hyperlink{classThe}{The}} virtual address of the mapping

Can be invoked from any context.

Requires careful handling when nesting multiple mappings because the map management is stack based. \mbox{\hyperlink{classThe}{The}} unmap has to be in the reverse order of the map operation\+:

addr1 = kmap\+\_\+local\+\_\+page(page1); addr2 = kmap\+\_\+local\+\_\+page(page2); ... \mbox{\hyperlink{highmem-internal_8h_a769f5d38123c52221df2134f5f5bdc25}{kunmap\+\_\+local(addr2)}}; \mbox{\hyperlink{highmem-internal_8h_a769f5d38123c52221df2134f5f5bdc25}{kunmap\+\_\+local(addr1)}};

Unmapping addr1 before addr2 is invalid and causes malfunction.

Contrary to \mbox{\hyperlink{include_2linux_2highmem_8h_a628341c170d47e771c023c419d0416b9}{kmap()}} mappings the mapping is only valid in the context of the caller and cannot be handed to other contexts.

On C\+O\+N\+F\+I\+G\+\_\+\+H\+I\+G\+H\+M\+EM=n kernels and for low memory pages this returns the virtual address of the direct mapping. Only real highmem pages are temporarily mapped.

While it is significantly faster than \mbox{\hyperlink{include_2linux_2highmem_8h_a628341c170d47e771c023c419d0416b9}{kmap()}} for the higmem case it comes with restrictions about the pointer validity. Only use when really necessary.

On H\+I\+G\+H\+M\+EM enabled systems mapping a highmem page has the side effect of disabling migration in order to keep the virtual address stable across preemption. No caller of \mbox{\hyperlink{include_2linux_2highmem_8h_aabdbf9cd91e3746d09f067ef372d06ed}{kmap\+\_\+local\+\_\+page()}} can rely on this side effect.

kmap\+\_\+atomic -\/ Atomically map a page for temporary usage -\/ Deprecated!

Returns\+: \mbox{\hyperlink{classThe}{The}} virtual address of the mapping

Effectively a wrapper around \mbox{\hyperlink{include_2linux_2highmem_8h_aabdbf9cd91e3746d09f067ef372d06ed}{kmap\+\_\+local\+\_\+page()}} which disables pagefaults and preemption.

Do not use in new code. Use \mbox{\hyperlink{include_2linux_2highmem_8h_aabdbf9cd91e3746d09f067ef372d06ed}{kmap\+\_\+local\+\_\+page()}} instead.
