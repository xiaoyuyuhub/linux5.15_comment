\doxysubsection{Detailed Description}
struct \mbox{\hyperlink{structspi__board__info}{spi\+\_\+board\+\_\+info}} -\/ board-\/specific template for a S\+PI device @modalias\+: Initializes \mbox{\hyperlink{structspi__device_a15b16bf44d7ec92cf3ff89773b3376a4}{spi\+\_\+device.\+modalias}}; identifies the driver. @platform\+\_\+data\+: Initializes spi\+\_\+device.\+platform\+\_\+data; the particular data stored there is driver-\/specific. @swnode\+: Software node for the device. @controller\+\_\+data\+: Initializes \mbox{\hyperlink{structspi__device_a46a134775aea20e4243e5bfc80e99dd8}{spi\+\_\+device.\+controller\+\_\+data}}; some controllers need hints about hardware setup, e.\+g. for D\+MA. @irq\+: Initializes \mbox{\hyperlink{structspi__device_a8a71c551de1f27858f3bf6a6d4efa6e4}{spi\+\_\+device.\+irq}}; depends on how the board is wired. @max\+\_\+speed\+\_\+hz\+: Initializes \mbox{\hyperlink{structspi__device_af0c89617539070b8a2ddfc7d9ea9df90}{spi\+\_\+device.\+max\+\_\+speed\+\_\+hz}}; based on limits from the chip datasheet and board-\/specific signal quality issues. @bus\+\_\+num\+: Identifies which \mbox{\hyperlink{structspi__controller}{spi\+\_\+controller}} parents the \mbox{\hyperlink{structspi__device}{spi\+\_\+device}}; unused by \mbox{\hyperlink{linux_2spi_2spi_8h_adbf26bd2e62ad98aa1e8192458cf2f95}{spi\+\_\+new\+\_\+device()}}, and otherwise depends on board wiring. @chip\+\_\+select\+: Initializes \mbox{\hyperlink{structspi__device_a623eefe74cd15be73aa51a9ce5d2ce65}{spi\+\_\+device.\+chip\+\_\+select}}; depends on how the board is wired. @mode\+: Initializes \mbox{\hyperlink{structspi__device_a4c9ac4cfceebfc041eff42be3fd35446}{spi\+\_\+device.\+mode}}; based on the chip datasheet, board wiring (some devices support both 3W\+I\+RE and standard modes), and possibly presence of an inverter in the chipselect path.

When adding new S\+PI devices to the device tree, these structures serve as a partial device template. They hold information which can\textquotesingle{}t always be determined by drivers. Information that probe() can establish (such as the default transfer wordsize) is not included here.

These structures are used in two places. Their primary role is to be stored in tables of board-\/specific device descriptors, which are declared early in board initialization and then used (much later) to populate a controller\textquotesingle{}s device tree after the that controller\textquotesingle{}s driver initializes. A secondary (and atypical) role is as a parameter to \mbox{\hyperlink{linux_2spi_2spi_8h_adbf26bd2e62ad98aa1e8192458cf2f95}{spi\+\_\+new\+\_\+device()}} call, which happens after those controller drivers are active in some dynamic board configuration models.
