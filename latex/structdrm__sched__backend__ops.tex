@timedout\+\_\+job\+: Called when a job has taken too long to execute, to trigger G\+PU recovery.

This method is called in a workqueue context.

Drivers typically issue a reset to recover from G\+PU hangs, and this procedure usually follows the following workflow\+:


\begin{DoxyEnumerate}
\item Stop the scheduler using \mbox{\hyperlink{gpu__scheduler_8h_ad588e7e8b46d964340c3f353434792b9}{drm\+\_\+sched\+\_\+stop()}}. This will park the scheduler thread and cancel the timeout work, guaranteeing that nothing is queued while we reset the hardware queue
\item Try to gracefully stop non-\/faulty jobs (optional)
\item Issue a G\+PU reset (driver-\/specific)
\item Re-\/submit jobs using \mbox{\hyperlink{gpu__scheduler_8h_a2c79ec18a5d62d2a4a66398002575b18}{drm\+\_\+sched\+\_\+resubmit\+\_\+jobs()}}
\item Restart the scheduler using \mbox{\hyperlink{gpu__scheduler_8h_acf839fcdb9966e0ae682bd91ff4107d6}{drm\+\_\+sched\+\_\+start()}}. At that point, new jobs can be queued, and the scheduler thread is unblocked
\end{DoxyEnumerate}

Note that some G\+P\+Us have distinct hardware queues but need to reset the G\+PU globally, which requires extra synchronization between the timeout handler of the different \&\mbox{\hyperlink{structdrm__gpu__scheduler}{drm\+\_\+gpu\+\_\+scheduler}}. One way to achieve this synchronization is to create an ordered workqueue (using \mbox{\hyperlink{linux_2workqueue_8h_ae072f2ec00123e4d113da3421cea07ef}{alloc\+\_\+ordered\+\_\+workqueue()}}) at the driver level, and pass this queue to \mbox{\hyperlink{gpu__scheduler_8h_a5e40fb0faf0fe41c0ef6cf27e0974548}{drm\+\_\+sched\+\_\+init()}}, to guarantee that timeout handlers are executed sequentially. \mbox{\hyperlink{classThe}{The}} above workflow needs to be slightly adjusted in that case\+:


\begin{DoxyEnumerate}
\item Stop all schedulers impacted by the reset using \mbox{\hyperlink{gpu__scheduler_8h_ad588e7e8b46d964340c3f353434792b9}{drm\+\_\+sched\+\_\+stop()}}
\item Try to gracefully stop non-\/faulty jobs on all queues impacted by the reset (optional)
\item Issue a G\+PU reset on all faulty queues (driver-\/specific)
\item Re-\/submit jobs on all schedulers impacted by the reset using \mbox{\hyperlink{gpu__scheduler_8h_a2c79ec18a5d62d2a4a66398002575b18}{drm\+\_\+sched\+\_\+resubmit\+\_\+jobs()}}
\item Restart all schedulers that were stopped in step \#1 using \mbox{\hyperlink{gpu__scheduler_8h_acf839fcdb9966e0ae682bd91ff4107d6}{drm\+\_\+sched\+\_\+start()}}
\end{DoxyEnumerate}

Return D\+R\+M\+\_\+\+G\+P\+U\+\_\+\+S\+C\+H\+E\+D\+\_\+\+S\+T\+A\+T\+\_\+\+N\+O\+M\+I\+N\+AL, when all is normal, and the underlying driver has started or completed recovery.

Return D\+R\+M\+\_\+\+G\+P\+U\+\_\+\+S\+C\+H\+E\+D\+\_\+\+S\+T\+A\+T\+\_\+\+E\+N\+O\+D\+EV, if the device is no longer available, i.\+e. has been unplugged.
