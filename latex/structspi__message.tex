\doxysubsection{Detailed Description}
struct \mbox{\hyperlink{structspi__message}{spi\+\_\+message}} -\/ one multi-\/segment S\+PI transaction @transfers\+: list of transfer segments in this transaction @spi\+: S\+PI device to which the transaction is queued @is\+\_\+dma\+\_\+mapped\+: if true, the caller provided both dma and cpu virtual addresses for each transfer buffer @complete\+: called to report transaction completions @context\+: the argument to \mbox{\hyperlink{structspi__message_ab27eee9bd1f9109f6d88028b303ba198}{complete()}} when it\textquotesingle{}s called @frame\+\_\+length\+: the total number of bytes in the message @actual\+\_\+length\+: the total number of bytes that were transferred in all successful segments @status\+: zero for success, else negative errno @queue\+: for use by whichever driver currently owns the message @state\+: for use by whichever driver currently owns the message @resources\+: for resource management when the spi message is processed

A @spi\+\_\+message is used to execute an atomic sequence of data transfers, each represented by a struct \mbox{\hyperlink{structspi__transfer}{spi\+\_\+transfer}}. \mbox{\hyperlink{classThe}{The}} sequence is \char`\"{}atomic\char`\"{} in the sense that no other \mbox{\hyperlink{structspi__message}{spi\+\_\+message}} may use that S\+PI bus until that sequence completes. On some systems, many such sequences can execute as a single programmed D\+MA transfer. On all systems, these messages are queued, and might complete after transactions to other devices. Messages sent to a given \mbox{\hyperlink{structspi__device}{spi\+\_\+device}} are always executed in F\+I\+FO order.

\mbox{\hyperlink{classThe}{The}} code that submits an \mbox{\hyperlink{structspi__message}{spi\+\_\+message}} (and its spi\+\_\+transfers) to the lower layers is responsible for managing its memory. Zero-\/initialize every field you don\textquotesingle{}t set up explicitly, to insulate against future A\+PI updates. After you submit a message and its transfers, ignore them until its completion callback.
