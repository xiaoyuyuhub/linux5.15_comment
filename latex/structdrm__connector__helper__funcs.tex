@atomic\+\_\+check\+:

This hook is used to validate connector state. This function is called from \&drm\+\_\+atomic\+\_\+helper\+\_\+check\+\_\+modeset, and is called when a connector property is set, or a modeset on the crtc is forced.

Because \&drm\+\_\+atomic\+\_\+helper\+\_\+check\+\_\+modeset may be called multiple times, this function should handle being called multiple times as well.

This function is also allowed to inspect any other object\textquotesingle{}s state and can add more state objects to the atomic commit if needed. Care must be taken though to ensure that state check and compute functions for these added states are all called, and derived state in other objects all updated. Again the recommendation is to just call check helpers until a maximal configuration is reached.

N\+O\+TE\+:

This function is called in the check phase of an atomic update. \mbox{\hyperlink{classThe}{The}} driver is not allowed to change anything outside of the free-\/standing state objects passed-\/in or assembled in the overall \&\mbox{\hyperlink{structdrm__atomic__state}{drm\+\_\+atomic\+\_\+state}} update tracking structure.

@get\+\_\+modes\+:

This function should fill in all modes currently valid for the sink into the \&\mbox{\hyperlink{structdrm__connector_aca058b760dafc17b10adff53e41cf334}{drm\+\_\+connector.\+probed\+\_\+modes}} list. It should also update the E\+D\+ID property by calling \mbox{\hyperlink{drm__connector_8h_a7e99ee017264287d9b98bd7fb992e3fd}{drm\+\_\+connector\+\_\+update\+\_\+edid\+\_\+property()}}.

\mbox{\hyperlink{classThe}{The}} usual way to implement this is to cache the E\+D\+ID retrieved in the probe callback somewhere in the driver-\/private connector structure. In this function drivers then parse the modes in the E\+D\+ID and add them by calling \mbox{\hyperlink{drm__edid_8h_ad27cbab837eded8539aaebc12fc4524f}{drm\+\_\+add\+\_\+edid\+\_\+modes()}}. But connectors that drive a fixed panel can also manually add specific modes using \mbox{\hyperlink{drm__modes_8h_aa6761a8ef6de87bb59ea3001eb061ea8}{drm\+\_\+mode\+\_\+probed\+\_\+add()}}. Drivers which manually add modes should also make sure that the \&\mbox{\hyperlink{structdrm__connector_a0d50bee9a7ac3517f5b3a63892595018}{drm\+\_\+connector.\+display\+\_\+info}}, \&drm\+\_\+connector.\+width\+\_\+mm and \&drm\+\_\+connector.\+height\+\_\+mm fields are filled in.

Note that the caller function will automatically add standard V\+E\+SA D\+MT modes up to 1024x768 if the .\mbox{\hyperlink{structdrm__connector__helper__funcs_a7f6f90d10ef0ecca69dffa53dba9527e}{get\+\_\+modes()}} helper operation returns no mode and if the connector status is connector\+\_\+status\+\_\+connected or connector\+\_\+status\+\_\+unknown. There is no need to call \mbox{\hyperlink{drm__edid_8h_a6208f3934847d57109596749d98edd04}{drm\+\_\+add\+\_\+modes\+\_\+noedid()}} manually in that case.

Virtual drivers that just want some standard V\+E\+SA mode with a given resolution can call \mbox{\hyperlink{drm__edid_8h_a6208f3934847d57109596749d98edd04}{drm\+\_\+add\+\_\+modes\+\_\+noedid()}}, and mark the preferred one using \mbox{\hyperlink{drm__edid_8h_a3c0053f90b35e907ddce45d3cb53e37e}{drm\+\_\+set\+\_\+preferred\+\_\+mode()}}.

This function is only called after the @detect hook has indicated that a sink is connected and when the E\+D\+ID isn\textquotesingle{}t overridden through sysfs or the kernel commandline.

This callback is used by the probe helpers in e.\+g. \mbox{\hyperlink{drm__probe__helper_8h_a9ebe8e4cf04255f7cf4a17ee33927479}{drm\+\_\+helper\+\_\+probe\+\_\+single\+\_\+connector\+\_\+modes()}}.

@mode\+\_\+valid\+\_\+ctx\+:

Callback to validate a mode for a connector, irrespective of the specific display configuration.

This callback is used by the probe helpers to filter the mode list (which is usually derived from the E\+D\+ID data block from the sink). See e.\+g. \mbox{\hyperlink{drm__probe__helper_8h_a9ebe8e4cf04255f7cf4a17ee33927479}{drm\+\_\+helper\+\_\+probe\+\_\+single\+\_\+connector\+\_\+modes()}}.

This function is optional, and is the atomic version of \&\mbox{\hyperlink{structdrm__connector__helper__funcs_a19f40eeb33610c5b8c99d4ae8b0bcfa0}{drm\+\_\+connector\+\_\+helper\+\_\+funcs.\+mode\+\_\+valid}}.

To allow for accessing the atomic state of modesetting objects, the helper libraries always call this with ctx set to a valid context, and \&\mbox{\hyperlink{structdrm__mode__config_aee2e0dcbff3f5dc352d73871a619687c}{drm\+\_\+mode\+\_\+config.\+connection\+\_\+mutex}} will always be locked with the ctx parameter set to @ctx. This allows for taking additional locks as required.

Even though additional locks may be acquired, this callback is still expected not to take any constraints into account which would be influenced by the currently set display state -\/ such constraints should be handled in the driver\textquotesingle{}s atomic check. For example, if a connector shares display bandwidth with other connectors then it would be ok to validate the minimum bandwidth requirement of a mode against the maximum possible bandwidth of the connector. But it wouldn\textquotesingle{}t be ok to take the current bandwidth usage of other connectors into account, as this would change depending on the display state.
