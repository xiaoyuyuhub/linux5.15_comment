\doxysubsection{Detailed Description}
struct \mbox{\hyperlink{structdma__buf}{dma\+\_\+buf}} -\/ shared buffer object

This represents a shared buffer, created by calling \mbox{\hyperlink{linux_2dma-buf_8h_aef3ce8ba26b66f24f44f43bf6d84d693}{dma\+\_\+buf\+\_\+export()}}. \mbox{\hyperlink{classThe}{The}} userspace representation is a normal file descriptor, which can be created by calling \mbox{\hyperlink{linux_2dma-buf_8h_aa76e35b40bda94247314e6c785e6a06f}{dma\+\_\+buf\+\_\+fd()}}.

Shared dma buffers are reference counted using \mbox{\hyperlink{linux_2dma-buf_8h_a9e97bb6e0096069307146b21f4738450}{dma\+\_\+buf\+\_\+put()}} and \mbox{\hyperlink{linux_2dma-buf_8h_a69787e251eb255a61faff0bfe4caa29a}{get\+\_\+dma\+\_\+buf()}}.

\mbox{\hyperlink{classDevice}{Device}} D\+MA access is handled by the separate \&struct \mbox{\hyperlink{structdma__buf__attachment}{dma\+\_\+buf\+\_\+attachment}}.

I\+M\+P\+L\+I\+C\+IT S\+Y\+N\+C\+H\+R\+O\+N\+I\+Z\+A\+T\+I\+ON R\+U\+L\+ES\+:

Drivers which support implicit synchronization of buffer access as e.\+g. exposed in {\ttfamily Implicit Fence Poll Support}\+\_\+ must follow the below rules.


\begin{DoxyItemize}
\item Drivers must add a shared fence through \mbox{\hyperlink{dma-resv_8h_aa73e720edb1f7c99a4b5f35dcd8ca081}{dma\+\_\+resv\+\_\+add\+\_\+shared\+\_\+fence()}} for anything the userspace A\+PI considers a read access. This highly depends upon the A\+PI and window system.
\item Similarly drivers must set the exclusive fence through \mbox{\hyperlink{dma-resv_8h_a5fe186f9221c2fd8cfb31047d06abea2}{dma\+\_\+resv\+\_\+add\+\_\+excl\+\_\+fence()}} for anything the userspace A\+PI considers write access.
\item Drivers may just always set the exclusive fence, since that only causes unecessarily synchronization, but no correctness issues.
\item Some drivers only expose a synchronous userspace A\+PI with no pipelining across drivers. These do not set any fences for their access. An example here is v4l.
\end{DoxyItemize}

D\+Y\+N\+A\+M\+IC I\+M\+P\+O\+R\+T\+ER R\+U\+L\+ES\+:

Dynamic importers, see \mbox{\hyperlink{linux_2dma-buf_8h_a66346ec42b185a488b379c1f5ff32655}{dma\+\_\+buf\+\_\+attachment\+\_\+is\+\_\+dynamic()}}, have additional constraints on how they set up fences\+:


\begin{DoxyItemize}
\item Dynamic importers must obey the exclusive fence and wait for it to signal before allowing access to the buffer\textquotesingle{}s underlying storage through the device.
\item Dynamic importers should set fences for any access that they can\textquotesingle{}t disable immediately from their \&\mbox{\hyperlink{structdma__buf__attach__ops_a24ca8e6f1327d02a13a90b72e92c76df}{dma\+\_\+buf\+\_\+attach\+\_\+ops.\+move\+\_\+notify}} callback.
