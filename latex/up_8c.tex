\mbox{\hyperlink{kernel_2smp_8c_a99e7cf492ea706d601c8c11e9323f4f3}{smp\+\_\+call\+\_\+function\+\_\+single\+\_\+async()}} -\/ Run an asynchronous function on a specific C\+PU. @cpu\+: \mbox{\hyperlink{classThe}{The}} C\+PU to run on. @csd\+: Pre-\/allocated and setup data structure

Like \mbox{\hyperlink{kernel_2smp_8c_a01d34c6f7f3677880f1b4709c1c0922c}{smp\+\_\+call\+\_\+function\+\_\+single()}}, but the call is asynchonous and can thus be done from contexts with disabled interrupts.

\mbox{\hyperlink{classThe}{The}} caller passes his own pre-\/allocated data structure (ie\+: embedded in an object) and is responsible for synchronizing it such that the I\+P\+Is performed on the @csd are strictly serialized.

If the function is called with one csd which has not yet been processed by previous call to \mbox{\hyperlink{kernel_2smp_8c_a99e7cf492ea706d601c8c11e9323f4f3}{smp\+\_\+call\+\_\+function\+\_\+single\+\_\+async()}}, the function will return immediately with -\/E\+B\+U\+SY showing that the csd object is still in progress.

N\+O\+TE\+: Be careful, there is unfortunately no current debugging facility to validate the correctness of this serialization.
